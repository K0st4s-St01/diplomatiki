\chapter{Εισαγωγή}

Η ασφαλής επικοινωνία σε κατανεμημένα συστήματα αποτελεί ένα από τα θεμελιώδη προβλήματα της σύγχρονης κρυπτογραφίας. Σε περιβάλλοντα όπου πολλοί χρήστες ή κόμβοι πρέπει να συνεργαστούν, η δημιουργία ενός κοινού μυστικού κλειδιού με ασφαλή και αποδοτικό τρόπο είναι απαραίτητη για την προστασία της επικοινωνίας.

Τα πρωτόκολλα συμφωνίας ομαδικού κλειδιού (Group Key Agreement protocols) επιτρέπουν σε ένα σύνολο συμμετεχόντων να καταλήξουν σε ένα κοινό κρυπτογραφικό κλειδί μέσω ενός μη ασφαλούς καναλιού επικοινωνίας, χωρίς να απαιτείται πλήρης εμπιστοσύνη σε έναν κεντρικό φορέα. Ωστόσο, η υλοποίηση τέτοιων πρωτοκόλλων σε πραγματικά αποκεντρωμένα περιβάλλοντα συνοδεύεται από προκλήσεις που σχετίζονται με το επικοινωνιακό κόστος, την υπολογιστική πολυπλοκότητα και την ανθεκτικότητα σε κακόβουλες ενέργειες.

Τα τελευταία χρόνια, η τεχνολογία blockchain έχει χρησιμοποιηθεί ως μηχανισμός ενίσχυσης της ασφάλειας σε κατανεμημένα συστήματα, παρέχοντας ιδιότητες όπως ακεραιότητα, διαφάνεια και μη αποποίηση ευθύνης. Πλατφόρμες όπως το Hyperledger Fabric επιτρέπουν την ανάπτυξη permissioned blockchain δικτύων, τα οποία είναι κατάλληλα για επιχειρησιακές και ελεγχόμενες εφαρμογές.

Στο πλαίσιο αυτό, η παρούσα διπλωματική εργασία υλοποιεί και αξιολογεί το πρωτόκολλο Blockchain Dynamic Group Key Agreement (BDGKA), το οποίο έχει προταθεί στη βιβλιογραφία για τη δημιουργία ασφαλούς ομαδικού κλειδιού σε αποκεντρωμένα περιβάλλοντα. Το πρωτόκολλο συνδυάζει τεχνικές βασισμένες σε bilinear pairings με υποδομή blockchain, με στόχο την εξασφάλιση επαληθεύσιμης και ανθεκτικής διαδικασίας ανταλλαγής μηνυμάτων.

Η κύρια συμβολή της παρούσας εργασίας δεν έγκειται στον σχεδιασμό νέου πρωτοκόλλου, αλλά στην υλοποίηση, ανάλυση και πειραματική αξιολόγηση της απόδοσης του BDGKA σε πραγματικό περιβάλλον. Συγκεκριμένα, μελετάται η συμπεριφορά του πρωτοκόλλου ως προς τον χρόνο εκτέλεσης, το επικοινωνιακό κόστος  καθώς και η κλιμάκωσή του σε συνάρτηση με τον αριθμό των συμμετεχόντων κόμβων.

Η υλοποίηση πραγματοποιήθηκε σε περιβάλλον Linux με χρήση Docker containers για την ανάπτυξη δικτύου Hyperledger Fabric . Οι κόμβοι του συστήματος υλοποιήθηκαν σε Java με χρήση του Spring Boot , ενώ οι κρυπτογραφικές λειτουργίες βασίστηκαν στη βιβλιοθήκη JPBC για την υποστήριξη bilinear pairings και πράξεων σε ελλειπτικές καμπύλες.


\section{Στόχοι της Εργασίας}

Στόχος της παρούσας διπλωματικής εργασίας είναι η υλοποίηση και η πειραματική αξιολόγηση του πρωτοκόλλου Blockchain Dynamic Group Key Agreement σε ένα πραγματικό περιβάλλον blockchain βασισμένο στο Hyperledger Fabric.

Αρχικά πραγματοποιείται η μελέτη του θεωρητικού και μαθηματικού υποβάθρου που απαιτείται για την κατανόηση του πρωτοκόλλου. Συγκεκριμένα παρουσιάζονται βασικές έννοιες της κρυπτογραφίας δημοσίου κλειδιού, των ελλειπτικών καμπυλών, των διγραμμικών απεικονίσεων, καθώς και των πρωτοκόλλων συμφωνίας κλειδιού ομάδας.

Στη συνέχεια αναλύεται η λειτουργία του πρωτοκόλλου BDGKA και παρουσιάζονται τα επιμέρους στάδια εκτέλεσής του. Ιδιαίτερη έμφαση δίνεται στον τρόπο δημιουργίας του ομαδικού κλειδιού, στους μηχανισμούς επαλήθευσης των συμμετεχόντων και στις ιδιότητες ασφαλείας που παρέχει το πρωτόκολλο.

Έπειτα σχεδιάζεται και αναπτύσσεται μία ολοκληρωμένη υλοποίηση του πρωτοκόλλου με χρήση της γλώσσας Java και του πλαισίου Spring Boot. Η υλοποίηση ενσωματώνεται σε δίκτυο Hyperledger Fabric, όπου τα παραγόμενα δεδομένα αποθηκεύονται στο blockchain μέσω κατάλληλου έξυπνου συμβολαίου.

Τέλος, πραγματοποιείται πειραματική αξιολόγηση της υλοποίησης μέσω μετρήσεων απόδοσης.

\section{Ομάδες (Groups)}

Έστω $G$ ένα μη κενό σύνολο εφοδιασμένο με μια δυαδική πράξη $\cdot : G \times G \to G$. 
Το ζεύγος $(G,\cdot)$ καλείται \textit{ομάδα} εάν ικανοποιούνται τα ακόλουθα αξιώματα:

Υπάρχει στοιχείο $e \in G$, το οποίο ονομάζεται \textit{ουδέτερο στοιχείο}, τέτοιο ώστε για κάθε $a \in G$ να ισχύει
\[
e \cdot a = a \cdot e = a.
\]

Για κάθε $a \in G$ υπάρχει στοιχείο $a^{-1} \in G$, το οποίο ονομάζεται \textit{αντίστροφο του $a$}, τέτοιο ώστε
\[
a \cdot a^{-1} = a^{-1} \cdot a = e.
\]

Επιπλέον, η πράξη είναι προσεταιριστική, δηλαδή για κάθε $a,b,c \in G$ ισχύει
\[
(a \cdot b)\cdot c = a \cdot (b \cdot c).
\]

Μια ομάδα $G$ λέγεται \textit{αβελιανή} όταν η πράξη είναι αντιμεταθετική, δηλαδή
\[
a \cdot b = b \cdot a, \quad \forall a,b \in G.
\]

\subsection{Κυκλικές Ομάδες και Γεννήτορες}

Έστω $G$ μια ομάδα και $g \in G$. Το υποσύνολο
\[
\langle g \rangle = \{ g^n \mid n \in \mathbb{Z} \}
\]
είναι η μικρότερη υποομάδα του $G$ που περιέχει το $g$ και καλείται \textit{κυκλική υποομάδα} που παράγεται από το $g$.

Αν ισχύει ότι $G = \langle g \rangle$ για κάποιο $g \in G$, τότε η ομάδα $G$ καλείται \textit{κυκλική ομάδα} και το στοιχείο $g$ ονομάζεται \textit{γεννήτορας} της $G$.

Γενικότερα, αν $S \subseteq G$, τότε η υποομάδα που παράγεται από το $S$, συμβολίζεται με $\langle S \rangle$, και ορίζεται ως η τομή όλων των υποομάδων του $G$ που περιέχουν το $S$.

\subsection{Πεπερασμένα Σώματα}

Ένα σώμα $F$ είναι ένα σύνολο εφοδιασμένο με δύο πράξεις $+$ και $\cdot$ έτσι ώστε:

Το $(F,+)$ να είναι αβελιανή ομάδα με ουδέτερο στοιχείο το $0$, και το $(F \setminus \{0\}, \cdot)$ να είναι επίσης αβελιανή ομάδα με ουδέτερο στοιχείο το $1$. Επιπλέον, για κάθε $a,b,c \in F$ ισχύει η επιμεριστική ιδιότητα
\[
a(b+c) = ab + ac.
\]

Ένα σώμα $F$ καλείται \textit{πεπερασμένο σώμα} όταν το σύνολό του είναι πεπερασμένο. Είναι γνωστό ότι η τάξη ενός πεπερασμένου σώματος είναι της μορφής
\[
|F| = p^n,
\]
όπου $p$ είναι πρώτος αριθμός και $n \in \mathbb{N}$. Σε αυτή την περίπτωση το σώμα συμβολίζεται συνήθως ως $\mathbb{F}_{p^n}$.

\subsection{Αριθμητική Modulo}

Έστω $n \ge 2$ ακέραιος. Ορίζουμε τη σχέση ισοδυναμίας στο $\mathbb{Z}$ ως
\[
a \equiv b \pmod{n} \quad \Longleftrightarrow \quad n \mid (a-b).
\]

Η σχέση αυτή διαμερίζει το σύνολο των ακεραίων σε κλάσεις ισοδυναμίας. Το σύνολο των κλάσεων συμβολίζεται με $\mathbb{Z}_n$ και γράφεται
\[
\mathbb{Z}_n = \{ [0], [1], \dots, [n-1] \}.
\]

Οι πράξεις πρόσθεσης και πολλαπλασιασμού ορίζονται μέσω αντιπροσώπων ως
\[
[a] + [b] = [a+b], \quad [a]\cdot[b] = [ab].
\]

Με τις πράξεις αυτές, το $\mathbb{Z}_n$ αποτελεί δακτύλιο με μοναδιαίο στοιχείο. Επιπλέον, το $\mathbb{Z}_n$ είναι σώμα αν και μόνο αν ο $n$ είναι πρώτος αριθμός.
\section{Συναρτήσεις Κατακερματισμού}

Μια κρυπτογραφική συνάρτηση κατακερματισμού $H$ δέχεται ως είσοδο ένα μήνυμα αυθαίρετου μεγέθους και παράγει μια έξοδο σταθερού μήκους. Η ιδιότητα αυτή επιτρέπει τη συμπίεση δεδομένων σε σταθερή αναπαράσταση ανεξαρτήτως μεγέθους εισόδου.

Επιπλέον, οι συναρτήσεις κατακερματισμού είναι μονόδρομες, δηλαδή είναι υπολογιστικά εύκολο να υπολογιστεί η τιμή $H(x)$ για δεδομένο $x$, ενώ είναι πρακτικά αδύνατη η αντίστροφη διαδικασία εύρεσης του $x$ από την τιμή $H(x)$. Για τον λόγο αυτό χρησιμοποιούνται ευρέως σε ψηφιακές υπογραφές, πρωτόκολλα ταυτοποίησης και συστήματα blockchain.

\section{Πρωτόκολλα Ανταλλαγής Κλειδιών}

\subsection{Πρωτόκολλο Diffie--Hellman}

Το πρωτόκολλο Diffie--Hellman (DH) επιτρέπει σε δύο μέρη, έστω $A$ και $B$, να συμφωνήσουν σε ένα κοινό μυστικό κλειδί μέσω ενός μη ασφαλούς καναλιού.

Έστω $G$ μια κυκλική ομάδα τάξης πρώτου $q$ με γεννήτορα $g$. 
Τα βήματα του πρωτοκόλλου είναι τα εξής:

Ο χρήστης $A$ επιλέγει τυχαίο $a \in \mathbb{Z}_q$ και υπολογίζει:
\[
A = g^a,
\]
το οποίο αποστέλλει στον $B$.

Ο χρήστης $B$ επιλέγει τυχαίο $b \in \mathbb{Z}_q$ και υπολογίζει:
\[
B = g^b,
\]
το οποίο αποστέλλει στον $A$.

Το κοινό μυστικό κλειδί υπολογίζεται ως:
\[
K = B^a = (g^b)^a = g^{ab} = (g^a)^b = A^b.
\]

Η ασφάλεια του πρωτοκόλλου βασίζεται στην υπόθεση Computational Diffie--Hellman (CDH).

\subsection{Ελλειπτική Εκδοχή Diffie--Hellman (ECDH)}

Στο Elliptic Curve Diffie--Hellman (ECDH), η ομάδα $G$ αντικαθίσταται από την αβελιανή ομάδα σημείων μιας ελλειπτικής καμπύλης $E(F)$.

Έστω $P \in E(F)$ σημείο γεννήτορας. Ο χρήστης $A$ επιλέγει μυστικό $a \in \mathbb{Z}_q$ και υπολογίζει:
\[
A = aP,
\]
ενώ ο χρήστης $B$ επιλέγει $b \in \mathbb{Z}_q$ και υπολογίζει:
\[
B = bP.
\]

Το κοινό μυστικό κλειδί προκύπτει ως:
\[
K = aB = a(bP) = abP = b(aP) = bA.
\]

Η ασφάλεια του πρωτοκόλλου βασίζεται στην υπολογιστική δυσκολία του Elliptic Curve Discrete Logarithm Problem (ECDLP).

\subsection{Group Diffie--Hellman}

Το Group Diffie--Hellman επεκτείνει το κλασικό DH σε ομάδα $n$ συμμετεχόντων $P_1, P_2, \dots, P_n$ σε κυκλική ομάδα $G$.

Κάθε συμμετέχων $P_i$ επιλέγει ιδιωτικό μυστικό $x_i \in \mathbb{Z}_q$ και υπολογίζει $g^{x_i}$.

Μέσω διαδοχικών ανταλλαγών και επαναληπτικών εκθετικοποιήσεων, οι συμμετέχοντες καταλήγουν σε κοινό μυστικό:
\[
K = g^{x_1 x_2 \cdots x_n}.
\]

Η πολυπλοκότητα του πρωτοκόλλου αυξάνεται με τον αριθμό των συμμετεχόντων, τόσο σε επικοινωνιακό όσο και σε υπολογιστικό επίπεδο.

\subsection{Contributory Key Agreement}

Τα πρωτόκολλα \textit{contributory key agreement} αποτελούν γενίκευση των group key exchange μηχανισμών, όπου το τελικό κλειδί εξαρτάται ισοδύναμα από τις συνεισφορές όλων των συμμετεχόντων και όχι από έναν κεντρικό παράγοντα.

Τυπικά, κάθε συμμετέχων $P_i$ συνεισφέρει μια τιμή $x_i$, και το τελικό κλειδί $K$ είναι συνάρτηση όλων των συνεισφορών:
\[
K = f(x_1, x_2, \dots, x_n),
\]
όπου η συνάρτηση $f$ είναι τέτοια ώστε κανένα υποσύνολο λιγότερο από όλους τους συμμετέχοντες να μην μπορεί να υπολογίσει το $K$.

Παραδείγματα τέτοιων πρωτοκόλλων περιλαμβάνουν επεκτάσεις του Diffie--Hellman σε ομάδες καθώς και πρωτόκολλα βασισμένα σε ελλειπτικές καμπύλες.

Η ασφάλεια βασίζεται συνήθως σε παραλλαγές του CDH ή του ECDLP, ανάλογα με το αλγεβρικό πλαίσιο στο οποίο υλοποιούνται.

\subsection{Υπολογιστική Ασφάλεια και Δύσκολα Μαθηματικά Προβλήματα}

Η ασφάλεια των σύγχρονων κρυπτογραφικών πρωτοκόλλων βασίζεται στην ύπαρξη
μαθηματικών προβλημάτων των οποίων η επίλυση θεωρείται υπολογιστικά μη εφικτή
με τα διαθέσιμα υπολογιστικά μέσα. Αντί να στηρίζεται στη μυστικότητα του
αλγορίθμου, η σύγχρονη κρυπτογραφία βασίζεται στη δυσκολία αντιστροφής
συγκεκριμένων μαθηματικών πράξεων.

Ένα από τα σημαντικότερα προβλήματα είναι το Πρόβλημα του Διακριτού
Λογαρίθμου (Discrete Logarithm Problem - DLP). Δοθέντων μιας κυκλικής ομάδας
$G$, ενός γεννήτορα $g$ και ενός στοιχείου $h$, ζητείται ο υπολογισμός του
εκθέτη $x$ έτσι ώστε:

\begin{equation}
h = g^x
\end{equation}

Παρότι ο υπολογισμός του $h$ από το $x$ είναι εύκολος, η αντίστροφη διαδικασία
θεωρείται εξαιρετικά δύσκολη όταν χρησιμοποιούνται κατάλληλες παράμετροι.

Πάνω σε αυτή τη δυσκολία βασίζεται και το πρόβλημα Computational
Diffie-Hellman (CDH). Δοθέντων των τιμών $g$, $g^a$ και $g^b$, ένας
επιτιθέμενος καλείται να υπολογίσει την τιμή:

\begin{equation}
g^{ab}
\end{equation}

χωρίς να γνωρίζει τα μυστικά $a$ και $b$.

Μία ακόμη ισχυρότερη υπόθεση είναι το Decisional Diffie-Hellman (DDH),
σύμφωνα με το οποίο ένας επιτιθέμενος καλείται να αποφασίσει αν μία τιμή
$g^c$ ισούται με $g^{ab}$ ή αποτελεί τυχαίο στοιχείο της ομάδας.

Οι παραπάνω υποθέσεις αποτελούν τη θεωρητική βάση πολλών πρωτοκόλλων
ανταλλαγής κλειδιών και χρησιμοποιούνται ευρέως τόσο στην κλασική
κρυπτογραφία όσο και στα σχήματα που βασίζονται σε διγραμμικά ζευγαρώματα.
\section{Κρυπτογραφία Ελλειπτικών Καμπυλών}

Οι ελλειπτικές καμπύλες αποτελούν μία από τις σημαντικότερες εξελίξεις της
σύγχρονης κρυπτογραφίας. Η χρήση τους επιτρέπει την επίτευξη υψηλού επιπέδου
ασφάλειας με σημαντικά μικρότερα μεγέθη κλειδιών σε σύγκριση με κλασικά
συστήματα όπως το RSA.

Μία ελλειπτική καμπύλη πάνω από ένα πεπερασμένο σώμα περιγράφεται από την
εξίσωση:

\begin{equation}
y^2 = x^3 + ax + b
\end{equation}

όπου οι παράμετροι $a$ και $b$ επιλέγονται κατά τρόπο ώστε η καμπύλη να μην
παρουσιάζει ιδιομορφίες.

Τα σημεία της καμπύλης μαζί με ένα ειδικό σημείο στο άπειρο σχηματίζουν μία
αβελιανή ομάδα. Η ιδιότητα αυτή επιτρέπει την εκτέλεση βασικών πράξεων όπως η
πρόσθεση σημείων και ο βαθμωτός πολλαπλασιασμός, οι οποίες αποτελούν το
θεμέλιο των κρυπτογραφικών πρωτοκόλλων που βασίζονται σε ελλειπτικές
καμπύλες.

Η ασφάλεια των συστημάτων αυτών βασίζεται στο πρόβλημα του διακριτού
λογαρίθμου πάνω σε ελλειπτικές καμπύλες (Elliptic Curve Discrete Logarithm
Problem - ECDLP). Το πρόβλημα αυτό θεωρείται σημαντικά δυσκολότερο ανά bit σε
σχέση με το αντίστοιχο πρόβλημα σε κλασικές ομάδες πεπερασμένων σωμάτων.

Για τον λόγο αυτό, ένα κλειδί ECC μεγέθους 256 bit θεωρείται ότι προσφέρει
επίπεδο ασφάλειας αντίστοιχο με ένα κλειδί RSA μεγέθους 3072 bit, γεγονός που
καθιστά την ECC ιδιαίτερα αποδοτική σε εφαρμογές με περιορισμένους πόρους.

\subsection{Ελλειπτικές Καμπύλες και Σημεία}

Μια ελλειπτική καμπύλη $E$ ορισμένη πάνω από ένα σώμα $F$ (συνήθως πεπερασμένο σώμα $\mathbb{F}_p$ ή $\mathbb{F}_{p^n}$) δίνεται σε απλουστευμένη μορφή Weierstrass ως:
\[
E: y^2 = x^3 + ax + b,
\]
όπου $a,b \in F$ και ικανοποιείται η συνθήκη μη εκφυλισμού:
\[
4a^3 + 27b^2 \neq 0.
\]

Το σύνολο των σημείων της καμπύλης ορίζεται ως:
\[
E(F) = \{(x,y) \in F \times F \mid y^2 = x^3 + ax + b\} \cup \{\mathcal{O}\},
\]
όπου $\mathcal{O}$ είναι το ουδέτερο στοιχείο, το λεγόμενο \textit{σημείο στο άπειρο}.

\subsection{Γεωμετρική και Αλγεβρική Δομή}

Το σύνολο $E(F)$ εφοδιασμένο με μια κατάλληλα ορισμένη πράξη σημείων σχηματίζει αβελιανή ομάδα με ουδέτερο στοιχείο το $\mathcal{O}$. Η πράξη αυτή ορίζεται γεωμετρικά ως εξής:

Για δύο σημεία $P, Q \in E(F)$, η ευθεία που τα ενώνει τέμνει την καμπύλη σε ένα τρίτο σημείο. Το συμμετρικό αυτού του σημείου ως προς τον άξονα $x$ ορίζει το άθροισμα:
\[
P + Q = R.
\]

Αν $P = Q$, τότε η πράξη ορίζεται μέσω της εφαπτομένης της καμπύλης στο σημείο $P$.

Το $\mathcal{O}$ λειτουργεί ως ουδέτερο στοιχείο:
\[
P + \mathcal{O} = P, \quad \forall P \in E(F).
\]

Επιπλέον, για κάθε $P = (x,y)$, το αντίστροφο είναι:
\[
-P = (x, -y).
\]

\subsection{Πολλαπλασιασμός με Βαθμωτό (Scalar Multiplication)}

Για ένα ακέραιο $k \in \mathbb{Z}$ και ένα σημείο $P \in E(F)$, ορίζουμε τον \textit{βαθμωτό πολλαπλασιασμό} ως:
\[
kP = \underbrace{P + P + \cdots + P}_{k \ \text{φορές}}.
\]

Ο υπολογισμός αυτός υλοποιείται αποδοτικά μέσω της μεθόδου \textit{διπλασιασμού και πρόσθεσης (double-and-add)}.

Ο scalar multiplication αποτελεί τον θεμελιώδη αλγόριθμο πάνω στον οποίο βασίζεται η κρυπτογραφία ελλειπτικών καμπυλών.

\subsection{Ασφάλεια της ECC}

Η ασφάλεια των συστημάτων ελλειπτικών καμπυλών βασίζεται στο υπολογιστικά δύσκολο πρόβλημα του \textit{Διακριτού Λογαρίθμου Ελλειπτικής Καμπύλης (Elliptic Curve Discrete Logarithm Problem - ECDLP)}.

Πιο συγκεκριμένα, δεδομένων των σημείων $P, Q \in E(F)$, όπου:
\[
Q = kP,
\]
είναι υπολογιστικά δύσκολο να βρεθεί ο ακέραιος $k$, ακόμη και αν είναι γνωστά τα $P$ και $Q$.

Η δυσκολία του προβλήματος ECDLP αποτελεί τη βάση της ασφάλειας της :contentReference[oaicite:0]{index=0}, και επιτρέπει μικρότερα κλειδιά σε σχέση με κλασικά κρυπτοσυστήματα όπως το RSA, διατηρώντας ισοδύναμο επίπεδο ασφάλειας.
\subsection{Πλεονεκτήματα της Κρυπτογραφίας Ελλειπτικών Καμπυλών}

Η κρυπτογραφία ελλειπτικών καμπυλών παρουσιάζει σημαντικά πλεονεκτήματα σε
σχέση με παραδοσιακές προσεγγίσεις δημόσιου κλειδιού.

Αρχικά, προσφέρει ισοδύναμο επίπεδο ασφάλειας με σημαντικά μικρότερα κλειδιά.
Η ιδιότητα αυτή μειώνει τις απαιτήσεις αποθήκευσης και περιορίζει τον όγκο των
δεδομένων που μεταδίδονται κατά την εκτέλεση κρυπτογραφικών πρωτοκόλλων.

Επιπλέον, οι μικρότερες παράμετροι οδηγούν σε ταχύτερες κρυπτογραφικές
πράξεις και μειωμένη κατανάλωση υπολογιστικών πόρων. Το χαρακτηριστικό αυτό
είναι ιδιαίτερα σημαντικό σε περιβάλλοντα περιορισμένων δυνατοτήτων, όπως οι
κινητές συσκευές, τα ενσωματωμένα συστήματα και οι συσκευές του Διαδικτύου
των Πραγμάτων (Internet of Things - IoT).

Ένα ακόμη σημαντικό πλεονέκτημα είναι η ευρεία υιοθέτησή της από σύγχρονα
πρότυπα ασφαλείας. Η ECC χρησιμοποιείται σε πρωτόκολλα όπως το TLS,
σε συστήματα ψηφιακών υπογραφών, σε εικονικά ιδιωτικά δίκτυα (VPN),
καθώς και σε πολλές πλατφόρμες blockchain.

Η αυξανόμενη χρήση των ελλειπτικών καμπυλών οδήγησε στην ανάπτυξη πιο
προηγμένων κρυπτογραφικών τεχνικών, όπως η Pairing-Based Cryptography.
Οι τεχνικές αυτές αξιοποιούν ειδικές κατηγορίες ελλειπτικών καμπυλών και
διγραμμικών απεικονίσεων για την υλοποίηση σύνθετων λειτουργιών, όπως
η ανταλλαγή ομαδικών κλειδιών, η κρυπτογραφία βασισμένη στην ταυτότητα
και οι σύντομες ψηφιακές υπογραφές.


\section{Δύσκολα Υπολογιστικά Προβλήματα}

\subsection{Πρόβλημα Διακριτού Λογαρίθμου (Discrete Logarithm Problem)}

Έστω $G$ μια κυκλική ομάδα πολλαπλασιαστικής γραφής, γεννήτορας $g \in G$ και στοιχείο $h \in G$. 
Το \textit{Πρόβλημα Διακριτού Λογαρίθμου} (Discrete Logarithm Problem - DLP) ορίζεται ως η εύρεση ενός ακεραίου $x \in \mathbb{Z}$ τέτοιου ώστε:
\[
g^x = h.
\]

Η υπολογιστική δυσκολία του προβλήματος εξαρτάται από την επιλογή της ομάδας $G$ και αποτελεί θεμελιώδη βάση για πλήθος κρυπτογραφικών πρωτοκόλλων.

\subsection{Υπολογιστικό Πρόβλημα Diffie--Hellman (Computational Diffie--Hellman)}

Έστω $G$ κυκλική ομάδα τάξης $q$ με γεννήτορα $g$. Δίνονται τα στοιχεία:
\[
(g, g^a, g^b),
\]
όπου $a,b \in \mathbb{Z}_q$ είναι άγνωστα.

Το \textit{Computational Diffie--Hellman problem (CDH)} συνίσταται στον υπολογισμό του:
\[
g^{ab}.
\]

Το πρόβλημα θεωρείται υπολογιστικά δύσκολο σε κατάλληλες ομάδες, ακόμη και όταν τα $g^a$ και $g^b$ είναι γνωστά.

\subsection{Αποφασιστικό Πρόβλημα Diffie--Hellman (Decisional Diffie--Hellman)}

Έστω $G$ κυκλική ομάδα τάξης $q$ με γεννήτορα $g$. Δίνονται τα στοιχεία:
\[
(g, g^a, g^b, g^c),
\]
όπου $a,b,c \in \mathbb{Z}_q$.

Το \textit{Decisional Diffie--Hellman problem (DDH)} είναι το πρόβλημα απόφασης αν:
\[
c = ab \pmod{q}
\]
ή ισοδύναμα αν:
\[
g^c = g^{ab}.
\]

Το πρόβλημα απαιτεί τη διάκριση μεταξύ του $g^{ab}$ και ενός τυχαίου στοιχείου της ομάδας $G$.

\subsection{Διγραμμικό Πρόβλημα Diffie--Hellman (Bilinear Diffie--Hellman)}

Έστω $(G_1, G_2, G_T)$ κυκλικές ομάδες τάξης πρώτου $p$, και μια διγραμμική απεικόνιση:
\[
e: G_1 \times G_2 \to G_T.
\]

Έστω $g \in G_1$ και $a,b,c \in \mathbb{Z}_p$. Δίνονται τα στοιχεία:
\[
(g, g^a, g^b, g^c).
\]

Το \textit{Bilinear Diffie--Hellman problem (BDH)} συνίσταται στον υπολογισμό του:
\[
e(g,g)^{abc} \in G_T.
\]

Η δυσκολία του προβλήματος εξαρτάται από τις ιδιότητες της διγραμμικής απεικόνισης και αποτελεί θεμελιώδες υπόβαθρο για ζευγοποιήσεις (pairings) σε σύγχρονα κρυπτογραφικά πρωτόκολλα.


\subsection{Υπολογιστικές Υποθέσεις και Προβλήματα: Σχέση CDH και DDH}

Στην κρυπτογραφία βασισμένη σε ομάδες, είναι θεμελιώδες να διακρίνουμε μεταξύ \textit{υπολογιστικών προβλημάτων} και \textit{υπολογιστικών υποθέσεων (assumptions)}. Ένα υπολογιστικό πρόβλημα ορίζεται τυπικά ως μια συνάρτηση ή σχέση που πρέπει να υπολογιστεί ή να αποφασιστεί, ενώ μια υπόθεση αναφέρεται στην παραδοχή ότι κάποιο τέτοιο πρόβλημα είναι υπολογιστικά ανεπίλυτο εντός πολυωνυμικού χρόνου για κατάλληλες παραμέτρους ασφάλειας.

Στο πλαίσιο των κυκλικών ομάδων $G$ τάξης πρώτου $q$, με γεννήτορα $g \in G$, τα προβλήματα Computational Diffie--Hellman (CDH) και Decisional Diffie--Hellman (DDH) αποτελούν δύο θεμελιώδεις έννοιες με στενή αλλά μη ισοδύναμη σχέση.

\subsubsection*{Το πρόβλημα CDH ως υπολογιστική υπόθεση}

Το \textit{Computational Diffie--Hellman problem (CDH)} δίνεται από τριάδα εισόδου:
\[
(g, g^a, g^b), \quad a,b \in \mathbb{Z}_q,
\]
και απαιτεί τον υπολογισμό του στοιχείου:
\[
g^{ab}.
\]

Η υπόθεση CDH (CDH assumption) διατυπώνεται ως η παραδοχή ότι δεν υπάρχει αποδοτικός (πολυωνυμικός) αλγόριθμος που να επιλύει το παραπάνω πρόβλημα με μη αμελητέα πιθανότητα επιτυχίας σε κατάλληλα επιλεγμένες ομάδες.

\subsubsection*{Το πρόβλημα DDH ως πρόβλημα διάκρισης}

Το \textit{Decisional Diffie--Hellman problem (DDH)} είναι πρόβλημα απόφασης. Δεδομένου του τετραπλού:
\[
(g, g^a, g^b, g^c),
\]
ο στόχος είναι να αποφασιστεί αν ισχύει:
\[
c = ab \pmod{q}
\quad \text{ή ισοδύναμα} \quad
g^c = g^{ab},
\]
ή αν το $g^c$ είναι τυχαίο στοιχείο της ομάδας $G$.

Η υπόθεση DDH (DDH assumption) διατυπώνει ότι δεν υπάρχει αποδοτικός αλγόριθμος που να διακρίνει το $g^{ab}$ από ένα τυχαίο στοιχείο του $G$ με μη αμελητέα διαφορά πιθανότητας.

\subsubsection*{Σχέση μεταξύ CDH και DDH}

Οι δύο υποθέσεις σχετίζονται ιεραρχικά ως προς την ισχύ τους. Συγκεκριμένα, η ευκολία επίλυσης του DDH συνεπάγεται επίλυση του CDH σε κατάλληλες κατασκευές, ενώ το αντίστροφο δεν ισχύει γενικά.

Πιο τυπικά, ισχύει η σχέση:
\[
\text{DDH} \;\Rightarrow\; \text{CDH},
\]
υπό την έννοια ότι ένας αλγόριθμος που λύνει το DDH μπορεί να χρησιμοποιηθεί για την κατασκευή αλγορίθμου που λύνει το CDH σε κατάλληλες ομάδες.

Ωστόσο, υπάρχουν ομάδες όπου το CDH θεωρείται δύσκολο, ενώ το DDH είναι εύκολο ή άκυρο ως υπόθεση, γεγονός που αναδεικνύει ότι οι δύο υποθέσεις δεν είναι ισοδύναμες.

Η επιλογή κατάλληλης ομάδας είναι συνεπώς κρίσιμη για την εγκυρότητα των υποθέσεων ασφάλειας σε πρωτόκολλα που βασίζονται σε Diffie--Hellman, όπως το Diffie--Hellman key exchange και σύγχρονα συστήματα βασισμένα σε elliptic curves.


\section{Pairing-Based Cryptography}

Η κρυπτογραφία που βασίζεται σε διγραμμικές απεικονίσεις
(Pairing-Based Cryptography) αποτελεί έναν από τους σημαντικότερους
κλάδους της σύγχρονης κρυπτογραφίας δημοσίου κλειδιού.
Η ανάπτυξή της ξεκίνησε στις αρχές της δεκαετίας του 2000, όταν
διαπιστώθηκε ότι συγκεκριμένες διγραμμικές απεικονίσεις σε
ελλειπτικές καμπύλες μπορούν να χρησιμοποιηθούν για την κατασκευή
νέων κρυπτογραφικών πρωτοκόλλων που δεν ήταν εφικτά με τις
παραδοσιακές τεχνικές.

Η βασική ιδέα της Pairing-Based Cryptography είναι η χρήση μιας
ειδικής συνάρτησης η οποία συνδέει δύο στοιχεία μιας ελλειπτικής
καμπύλης και παράγει ένα στοιχείο σε διαφορετική ομάδα.
Η ιδιότητα της διγραμμικότητας επιτρέπει την εκτέλεση σύνθετων
κρυπτογραφικών υπολογισμών, καθιστώντας δυνατή την υλοποίηση
πρωτοκόλλων ταυτοποίησης, ψηφιακών υπογραφών, κρυπτογραφίας
βασισμένης στην ταυτότητα και πρωτοκόλλων ομαδικής συμφωνίας
κλειδιών.

Στην παρούσα εργασία οι διγραμμικές απεικονίσεις αποτελούν το
θεμέλιο του πρωτοκόλλου BDGKA, καθώς επιτρέπουν τον ασφαλή
υπολογισμό ενός κοινού μυστικού κλειδιού μεταξύ πολλών
συμμετεχόντων χωρίς την ύπαρξη κεντρικού διαχειριστή.

\subsection{Bilinear Pairings}

Έστω δύο κυκλικές ομάδες πρώτης τάξης \(G_1\) και \(G_T\)
με κοινή τάξη \(q\).
Μία διγραμμική απεικόνιση ορίζεται ως η συνάρτηση

\[
e : G_1 \times G_1 \rightarrow G_T
\]

η οποία αντιστοιχίζει δύο στοιχεία της ομάδας \(G_1\)
σε ένα στοιχείο της ομάδας \(G_T\).

Η απεικόνιση αυτή πρέπει να είναι αποδοτικά υπολογίσιμη
και να ικανοποιεί συγκεκριμένες μαθηματικές ιδιότητες.
Η σημαντικότερη ιδιότητά της είναι ότι μετατρέπει
πολλαπλασιασμούς εκθετών σε πράξεις στην ομάδα στόχο,
γεγονός που επιτρέπει την κατασκευή προηγμένων
κρυπτογραφικών μηχανισμών.

Για στοιχεία \(P,Q \in G_1\) και εκθέτες
\(a,b \in \mathbb{Z}_q\) ισχύει:

\[
e(aP,bQ)=e(P,Q)^{ab}
\]

Η παραπάνω σχέση αποτελεί τη θεμελιώδη ιδιότητα
των bilinear pairings και είναι η βάση όλων των
pairing-based πρωτοκόλλων.

\subsection{Ιδιότητες}

Μία συνάρτηση \(e\) θεωρείται κατάλληλη για
κρυπτογραφική χρήση μόνο εάν ικανοποιεί τις
παρακάτω ιδιότητες.

\subsubsection*{Διγραμμικότητα (Bilinearity)}

Για όλα τα $u \in G_1$, $v \in G_2$ και $a,b \in \mathbb{Z}_p$ ισχύει:
\[
e(u^a, v^b) = e(u,v)^{ab}.
\]

Ισοδύναμα:
\[
e(u_1 u_2, v) = e(u_1, v)\, e(u_2, v), \quad
e(u, v_1 v_2) = e(u, v_1)\, e(u, v_2).
\]

\subsubsection*{Μη εκφυλισμός (Non-degeneracy)}

Η απεικόνιση $e$ δεν είναι τετριμμένη, δηλαδή:
\[
\exists u \in G_1, v \in G_2 \text{ τέτοια ώστε } e(u,v) \neq 1.
\]

Αυτό συνεπάγεται ότι η ζευγοποίηση διατηρεί μη τετριμμένη αλγεβρική πληροφορία.

\subsubsection*{Υπολογισιμότητα (Computability)}

Υπάρχει αποδοτικός αλγόριθμος που υπολογίζει το $e(u,v)$ για κάθε $u \in G_1$, $v \in G_2$ σε πολυωνυμικό χρόνο ως προς το μέγεθος των παραμέτρων ασφάλειας.

\subsection{Κατηγοριοποίηση Ζευγοποιήσεων}

Οι ζευγοποιήσεις ταξινομούνται σε τρεις τύπους ανάλογα με τη σχέση μεταξύ των ομάδων $G_1$ και $G_2$.

\subsubsection*{Type 1 (Συμμετρικές ζευγοποιήσεις)}

Ισχύει $G_1 = G_2$. Πρόκειται για συμμετρικές ζευγοποιήσεις, οι οποίες είναι ιστορικά οι πρώτες που μελετήθηκαν, αλλά συχνά δεν είναι αποδοτικές σε σύγχρονες υλοποιήσεις.

\subsubsection*{Type 2}

Υπάρχει ισομορφισμός μεταξύ $G_1$ και $G_2$, αλλά ο ισομορφισμός δεν είναι αποδοτικά υπολογίσιμος. Αυτό δημιουργεί περιορισμούς στη σχεδίαση πρωτοκόλλων.

\subsubsection*{Type 3}

Οι ομάδες $G_1$ και $G_2$ είναι διακριτές και δεν υπάρχει αποδοτικός ισομορφισμός μεταξύ τους. Αυτός ο τύπος θεωρείται ο πιο αποδοτικός και χρησιμοποιείται ευρέως στη σύγχρονη κρυπτογραφία.

\subsection{Τύποι Pairings}

Οι διγραμμικές απεικονίσεις διακρίνονται σε διαφορετικές κατηγορίες ανάλογα με τη δομή και τη σχέση μεταξύ των εμπλεκόμενων ομάδων. Στην περίπτωση όπου οι ομάδες εισόδου και στόχου ταυτίζονται, δηλαδή $G_1 = G_2$, η υλοποίηση είναι πιο απλή και συχνά πιο αποδοτική, καθώς δεν απαιτούνται πρόσθετες μετατροπές μεταξύ διαφορετικών αλγεβρικών δομών.

Σε μια πιο γενική περίπτωση, οι ομάδες $G_1$ και $G_2$ είναι διαφορετικές αλλά υπάρχει αποδοτικά υπολογίσιμος ισομορφισμός μεταξύ τους, συνήθως της μορφής
\[
\phi : G_2 \rightarrow G_1.
\]
Η ύπαρξη αυτής της απεικόνισης επιτρέπει τη μεταφορά υπολογισμών μεταξύ των ομάδων, χωρίς όμως να απαιτείται η ύπαρξη αντίστροφου ισομορφισμού.

Στην πιο γενική και κρυπτογραφικά ισχυρή περίπτωση, οι ομάδες $G_1$ και $G_2$ είναι διακριτές και δεν υπάρχει αποδοτικά υπολογίσιμος ισομορφισμός ούτε προς τη μία ούτε προς την άλλη κατεύθυνση. Η κατηγορία αυτή προσφέρει μεγαλύτερη ευελιξία και χρησιμοποιείται συχνά σε σύγχρονα pairing-based πρωτόκολλα, καθώς αποφεύγεται η ύπαρξη ανεπιθύμητων δομικών σχέσεων μεταξύ των ομάδων.

\subsection{Weil Pairing}

Το Weil pairing αποτελεί μία από τις πρώτες και θεμελιώδεις κατασκευές διγραμμικών απεικονίσεων πάνω σε ελλειπτικές καμπύλες και εισήχθη από τον André Weil στο πλαίσιο της αλγεβρικής γεωμετρίας. Η σημασία του έγκειται στο ότι παρέχει ένα θεωρητικό υπόβαθρο για την ανάπτυξη σύγχρονων κρυπτογραφικών pairings.

Στο πλαίσιο των ελλειπτικών καμπυλών, το Weil pairing ορίζεται πάνω σε σημεία πεπερασμένης τάξης και ικανοποιεί ιδιότητες διγραμμικότητας και εναλλαγής, οι οποίες το καθιστούν κατάλληλο για χρήση σε κρυπτογραφικά πρωτόκολλα.

Για τον υπολογισμό του Weil pairing στην πράξη χρησιμοποιείται ο αλγόριθμος του Miller, ο οποίος επιτρέπει τον αποδοτικό υπολογισμό συναρτήσεων της μορφής $f_{r,P}(Q)$. Ο υπολογισμός του pairing πραγματοποιείται συνήθως μέσω δύο εφαρμογών του Miller algorithm, ώστε να υπολογιστούν οι ποσότητες
\[
f_{r,P}(Q) \quad \text{και} \quad f_{r,Q}(P),
\]
οι οποίες στη συνέχεια συνδυάζονται για την παραγωγή του τελικού αποτελέσματος του ζευγαρώματος.

Κατά την εκτέλεση του αλγορίθμου μπορεί να εμφανιστούν ενδιάμεσα σημεία μη ορισμού (poles) ή μηδενισμοί στις υπολογιζόμενες συναρτήσεις. Η εμφάνιση τέτοιων περιπτώσεων συνδέεται με την αλγεβρική δομή των σημείων και υποδεικνύει ότι τα εμπλεκόμενα σημεία ανήκουν στην ίδια κυκλική υποομάδα.

Συγκεκριμένα, εάν ένα σημείο $Q$ ανήκει στην υποομάδα που παράγεται από το $P$, δηλαδή αν υπάρχει $\lambda \in \mathbb{Z}_q^*$ τέτοιο ώστε $Q = \lambda P$, τότε λόγω της διγραμμικότητας και της αντισυμμετρίας του Weil pairing ισχύει ότι
\[
e_{W,r}(P,Q) = e_{W,r}(P, \lambda P) = e_{W,r}(P,P)^\lambda.
\]

Ωστόσο, το Weil pairing είναι εναλλασσόμενο (alternating), γεγονός που συνεπάγεται ότι
\[
e_{W,r}(P,P) = 1.
\]
Κατά συνέπεια προκύπτει ότι
\[
e_{W,r}(P,Q) = 1,
\]
γεγονός που αντικατοπτρίζει τη δομική εξάρτηση των δύο σημείων μέσα στην ίδια κυκλική υποομάδα.
Για τον υπολογισμό του Weil pairing στην πράξη, χρησιμοποιείται ο Αλγόριθμος του Miller δύο φορές, ώστε να υπολογιστούν οι τιμές:

\[
f_{r,P}(Q) \quad \text{και} \quad f_{r,Q}(P)
\]

Στη συνέχεια, από τον συνδυασμό των παραπάνω μεγεθών προκύπτει το τελικό αποτέλεσμα του ζευγαρώματος.

Κατά την εκτέλεση του αλγορίθμου, είναι πιθανό να παρουσιαστούν ενδιάμεσα μηδενικά ή πόλοι στις υπολογιζόμενες συναρτήσεις. Σε αυτή την περίπτωση, η διαδικασία υποδεικνύει ότι το σημείο $Q$ ανήκει στον κυκλικό υποομάδα που παράγεται από το $P$, δηλαδή ότι είναι πολλαπλάσιο του $P$. Τότε προκύπτει ότι:

\[
e_{W,r}(P,Q) = 1
\]

Πράγματι, αν ισχύει ότι:

\[
Q = \lambda P
\]

τότε από τη γραμμικότητα και την εναλλαγή του Weil pairing έχουμε:

\[
e_{W,r}(P,Q) = e_{W,r}(P,P)^{\lambda}
\]

Ωστόσο, επειδή το Weil pairing είναι εναλλασσόμενο, ισχύει ότι:

\[
e_{W,r}(P,P) = 1
\]

και συνεπώς καταλήγουμε στο συμπέρασμα ότι:

\[
e_{W,r}(P,Q) = 1
\]


\subsection{Tate Pairing}

Η Tate pairing βασίζεται στη θεωρία των divisor classes και ορίζεται ως απεικόνιση:
\[
e_r: E[r] \times E(F_q)/rE(F_q) \rightarrow F_q^*/(F_q^*)^r.
\]

Σε πρακτικές εφαρμογές χρησιμοποιείται η βελτιωμένη εκδοχή (reduced Tate pairing), η οποία αποδίδει τιμές σε κυκλική υποομάδα.

Η Tate pairing είναι πιο αποδοτική από τη Weil pairing σε υπολογιστικό επίπεδο.

\subsection{Ate Pairing}

Η Ate pairing αποτελεί βελτιστοποίηση της Tate pairing και μειώνει το υπολογιστικό κόστος μειώνοντας τον εκθέτη της τελικής εκθετικοποίησης.

Χρησιμοποιείται ευρέως σε σύγχρονες βιβλιοθήκες ζευγοποιήσεων λόγω της υψηλής αποδοτικότητας.

\subsection{Pairing-Friendly Καμπύλες}

\subsubsection*{Barreto--Naehrig (BN) Curves}

Οι καμπύλες BN είναι οικογένεια ελλειπτικών καμπυλών κατάλληλων για αποδοτικές ζευγοποιήσεις με embedding degree $k=12$. Έχουν ευρεία χρήση σε πρακτικά συστήματα λόγω καλής ισορροπίας ασφάλειας και απόδοσης.

\subsubsection*{BLS Curves}

Οι BLS καμπύλες αποτελούν άλλη σημαντική οικογένεια pairing-friendly καμπυλών και χρησιμοποιούνται ευρέως σε πρωτόκολλα υπογραφών βασισμένων σε ζευγοποιήσεις (BLS signatures).

\subsection{Πλεονεκτήματα και Μειονεκτήματα των Ζευγοποιήσεων}

Οι διγραμμικές ζευγοποιήσεις επιτρέπουν την κατασκευή προηγμένων κρυπτογραφικών πρωτοκόλλων, όπως identity-based encryption, attribute-based encryption και short signatures.

Ωστόσο, παρουσιάζουν αυξημένο υπολογιστικό κόστος σε σχέση με κλασικά συστήματα βασισμένα σε discrete logarithm problems. Επιπλέον, απαιτούν προσεκτική επιλογή καμπυλών ώστε να αποφεύγονται γνωστές επιθέσεις που εκμεταλλεύονται το embedding degree και τις ιδιότητες της ομάδας στόχου $G_T$.
\section{Group Key Agreement}

Το \textit{Group Key Agreement (GKA)} αποτελεί ένα θεμελιώδες κρυπτογραφικό πρωτόκολλο, το οποίο επιτρέπει σε ένα σύνολο από συμμετέχοντες κόμβους
$U = \{U_1, U_2, \dots, U_n\}$ να συμφωνήσουν και να υπολογίσουν από κοινού ένα κοινό μυστικό κλειδί $GK$, το οποίο χρησιμοποιείται στη συνέχεια για την ασφαλή επικοινωνία μεταξύ τους. Η διαδικασία αυτή πραγματοποιείται μέσω ενός μη ασφαλούς καναλιού επικοινωνίας, γεγονός που σημαίνει ότι οποιοσδήποτε τρίτος μπορεί δυνητικά να παρακολουθεί την ανταλλαγή μηνυμάτων, χωρίς όμως να μπορεί να ανακτήσει το τελικό κλειδί.

Ένα βασικό χαρακτηριστικό του πρωτοκόλλου είναι η απουσία κεντρικής αρχής κατά τη φάση της δημιουργίας του κλειδιού. Δηλαδή, δεν υπάρχει ένας μοναδικός εξουσιοδοτημένος φορέας που να υπολογίζει ή να διανέμει το $GK$, αλλά αντίθετα όλοι οι συμμετέχοντες συμβάλλουν ενεργά στη διαδικασία παραγωγής του. Ως αποτέλεσμα, η τελική τιμή του κλειδιού προκύπτει από την αλληλεπίδραση όλων των συμμετεχόντων.

Ο στόχος του πρωτοκόλλου είναι όλοι οι νόμιμοι συμμετέχοντες να καταλήγουν στο ίδιο κοινό αποτέλεσμα, ανεξάρτητα από τη σειρά επικοινωνίας ή τον χρόνο συμμετοχής τους. Αυτό εκφράζεται μαθηματικά ως:

\[
GK_{U_1} = GK_{U_2} = \dots = GK_{U_n} = GK
\]

Η ασφάλεια του πρωτοκόλλου εξετάζεται υπό την παρουσία ενός ισχυρού και ενεργού αντιπάλου. Ο αντίπαλος αυτός θεωρείται ότι έχει τη δυνατότητα να παρακολουθεί πλήρως την επικοινωνία του δικτύου, να καταγράφει όλα τα μηνύματα που ανταλλάσσονται μεταξύ των κόμβων, καθώς και να επιχειρεί ενεργές επιθέσεις, όπως η τροποποίηση ή η επαναποστολή παλαιών μηνυμάτων (replay attacks). Επιπλέον, θεωρείται ότι μπορεί να αποκτήσει πρόσβαση σε ένα υποσύνολο των συμμετεχόντων κόμβων, οι οποίοι χαρακτηρίζονται ως παραβιασμένοι (corrupted nodes).

Παρά αυτές τις ισχυρές υποθέσεις επίθεσης, το πρωτόκολλο σχεδιάζεται έτσι ώστε να διατηρεί κρίσιμες ιδιότητες ασφάλειας. Πρώτον, εξασφαλίζεται η εμπιστευτικότητα (confidentiality), δηλαδή το κοινό μυστικό κλειδί $GK$ δεν αποκαλύπτεται σε καμία μη εξουσιοδοτημένη οντότητα, ακόμη και αν αυτή παρακολουθεί το σύνολο της επικοινωνίας. Δεύτερον, παρέχεται forward secrecy, πράγμα που σημαίνει ότι ένας κόμβος ο οποίος αποχωρεί από το δίκτυο δεν μπορεί να ανακτήσει ή να υπολογίσει μελλοντικά κλειδιά που παράγονται μετά την αποχώρησή του. Αντίστοιχα, εξασφαλίζεται backward secrecy, ώστε ένας νέος κόμβος που εισέρχεται στο σύστημα να μην μπορεί να ανακτήσει προηγούμενα κοινά κλειδιά τα οποία χρησιμοποιήθηκαν πριν τη συμμετοχή του. Τέλος, το πρωτόκολλο παρουσιάζει ανθεκτικότητα σε συνεργασία κακόβουλων κόμβων (resistance to collusion), δηλαδή ακόμη και αν πολλοί παραβιασμένοι συμμετέχοντες συνεργαστούν, δεν είναι σε θέση να αποκαλύψουν το $GK$.

Η ασφάλεια του Group Key Agreement βασίζεται σε θεμελιώδη και ευρέως αποδεκτά υπολογιστικά δύσκολα προβλήματα της κρυπτογραφίας. Συγκεκριμένα, στηρίζεται στη δυσκολία επίλυσης του Discrete Logarithm Problem (DLP), καθώς και στο Computational Bilinear Diffie-Hellman (CBDH) πρόβλημα, τα οποία θεωρούνται υπολογιστικά μη εφικτά για επαρκώς μεγάλες παραμέτρους.

Με βάση τα παραπάνω, κάθε κόμβος του συστήματος συμμετέχει ενεργά στη διαδικασία παραγωγής και επεξεργασίας των ενδιάμεσων τιμών, με αποτέλεσμα, παρότι οι υπολογισμοί πραγματοποιούνται κατανεμημένα και ανεξάρτητα, όλοι οι συμμετέχοντες να καταλήγουν τελικά στο ίδιο κοινό μυστικό κλειδί $GK$.

	\begin{algorithm}
		\caption{Miller's algorithm (general version)}

		\textbf{Input:}
		$r \in \mathbb{N}$,
		$I=\lfloor \log r \rfloor$,
		$P=(x_P,y_P)\in E[r](K)$,
		$Q=(x_Q,y_Q)\in E(K)$

		\vspace{0.2cm}

		\textbf{Output:}
		$f_{r,P}(Q)$

		\begin{algorithmic}[1]

		\State Compute the binary decomposition:
		\[
		r := \sum_{i=0}^{I} b_i 2^i
		\]
		Let $T=P$, $f=1$

		\For{$i$ in $[I-1..0]$}

		    \State $f = f^2 \mu_{T,T}(Q)$
    
		    \State $T = 2T$
    
		    \If{$b_i = 1$}
    
		        \State $f = f \mu_{T,P}(Q)$
        
		        \State $T = T + P$
        
		    \EndIf
    
		\EndFor

		\State \Return $f$

		\end{algorithmic}
	\end{algorithm}

	\begin{algorithm}
	\caption{Miller's Algorithm for Affine Short Weierstrass Coordinates}
	\begin{algorithmic}[1]

	\Require 
	$r \in \mathbb{N}$,
	$I=\lfloor \log r \rfloor$,
	$P=(x_P,y_P)\in E[r](K)$,
	$Q=(x_Q,y_Q)\in E(K)$

	\Ensure 
	$f_{r,P}(Q)$

	\State Compute the binary decomposition
	\[
	r=\sum_{i=0}^{I} b_i 2^i
	\]

	\State $T \gets P$
	\State $f_1 \gets 1$
	\State $f_2 \gets 1$

	\For{$i = I-1$ downto $0$}

	    \State
	    \[
	    \alpha \gets \frac{3x_T^2+a}{2y_T}
	    \]
	    \Comment{slope of the tangent of $E$ at $T$}

	    \State
	    \[
	    x_{2T} \gets \alpha^2 - 2x_T
	    \]

	    \State
	    \[
	    y_{2T} \gets -y_T - \alpha(x_{2T}-x_T)
	    \]

	    \State
	    \[
	    f_1 \gets f_1^2
	    \bigl(
	    y_Q-y_T-\alpha(x_Q-x_T)
	    \bigr)
	    \]

	    \State
	    \[
	    f_2 \gets f_2^2
	    \bigl(
	    x_Q+2x_T-\alpha^2
	    \bigr)
	    \]

	    \State $T \gets 2T$

	    \If{$b_i = 1$}

	        \State
	        \[
	        \alpha \gets
	        \frac{y_T-y_P}{x_T-x_P}
	        \]
	        \Comment{slope of the line through $P$ and $T$}

	        \State
	        \[
	        x_{T+P} \gets \alpha^2-x_T-x_P
	        \]

	        \State
	        \[
	        y_{T+P} \gets -y_T-\alpha(x_{T+P}-x_T)
	        \]

	        \State
	        \[
	        f_1 \gets
	        f_1
	        \bigl(
	        y_Q-y_T-\alpha(x_Q-x_T)
	        \bigr)
	        \]

	        \State
	        \[
	        f_2 \gets
	        f_2
	        \bigl(
	        x_Q+(x_P+x_T)-\alpha^2
	        \bigr)
	        \]

	        \State $T \gets T+P$

	    \EndIf

	\EndFor

	\State
	\[
	f_1 \gets f_1(x_Q-x_T)
	\]

	\State \Return
	\[
	\frac{f_1}{f_2}
	\]

	\end{algorithmic}
	\end{algorithm}

\chapter{Πρωτόκολλα Ομαδικής Συμφωνίας Κλειδιού (Group Key Agreement Protocols)}

\section{Εισαγωγή}

Τα πρωτόκολλα ομαδικής συμφωνίας κλειδιού (Group Key Agreement Protocols) επιτρέπουν σε μια ομάδα $n$ συμμετεχόντων να καταλήξουν σε ένα κοινό μυστικό κλειδί μέσω ενός μη ασφαλούς καναλιού. Σε αντίθεση με τα πρωτόκολλα ανταλλαγής κλειδιών δύο μερών, η πολυπλοκότητα και οι απαιτήσεις ασφάλειας αυξάνονται σημαντικά λόγω της δυναμικής φύσης των ομάδων.

\section{Βασικές Απαιτήσεις}

Τα πρωτόκολλα ομαδικής συμφωνίας κλειδιού πρέπει να ικανοποιούν συγκεκριμένες απαιτήσεις ασφάλειας και λειτουργικότητας, ώστε να μπορούν να χρησιμοποιηθούν σε πραγματικά κατανεμημένα περιβάλλοντα. Σε αντίθεση με τα απλά πρωτόκολλα ανταλλαγής κλειδιού μεταξύ δύο χρηστών, στην περίπτωση των ομάδων το πλήθος των συμμετεχόντων μπορεί να μεταβάλλεται δυναμικά, γεγονός που αυξάνει σημαντικά την πολυπλοκότητα του προβλήματος.

Βασική απαίτηση αποτελεί η εμπιστευτικότητα του ομαδικού κλειδιού. Το τελικό κλειδί πρέπει να είναι γνωστό μόνο στα έγκυρα μέλη της ομάδας και να μην μπορεί να υπολογιστεί από εξωτερικούς χρήστες ή από κόμβους που δεν συμμετέχουν νόμιμα στην εκτέλεση του πρωτοκόλλου. Η ιδιότητα αυτή είναι απαραίτητη, καθώς το ομαδικό κλειδί χρησιμοποιείται στη συνέχεια για την προστασία της επικοινωνίας μεταξύ των μελών.

Μία ακόμη σημαντική απαίτηση είναι η εμπρόσθια μυστικότητα (forward secrecy). Η ιδιότητα αυτή εξασφαλίζει ότι όταν ένα μέλος αποχωρεί από την ομάδα, δεν μπορεί να υπολογίσει μελλοντικά ομαδικά κλειδιά. Με τον τρόπο αυτό αποτρέπεται η πρόσβαση αποχωρησάντων χρηστών σε μελλοντικές επικοινωνίες της ομάδας. Η απαίτηση αυτή είναι ιδιαίτερα σημαντική σε δυναμικά συστήματα, όπου οι συμμετέχοντες μπορούν να αλλάζουν συχνά.

Αντίστοιχα, η αντίστροφη μυστικότητα (backward secrecy) εξασφαλίζει ότι ένα νέο μέλος που εισέρχεται στην ομάδα δεν μπορεί να αποκτήσει πρόσβαση σε παλαιότερα ομαδικά κλειδιά. Έτσι, προστατεύεται το ιστορικό της επικοινωνίας της ομάδας και αποτρέπεται η αποκάλυψη προηγούμενων δεδομένων σε νέους συμμετέχοντες.

Επιπλέον, σημαντική ιδιότητα είναι η ανεξαρτησία κλειδιών (key independence). Σύμφωνα με αυτή την απαίτηση, η γνώση ενός παλαιού ή μελλοντικού κλειδιού δεν πρέπει να επιτρέπει τον υπολογισμό άλλων κλειδιών της ομάδας. Κάθε ομαδικό κλειδί πρέπει να θεωρείται ανεξάρτητο από τα προηγούμενα και τα επόμενα, ώστε η παραβίαση μιας εκτέλεσης του πρωτοκόλλου να μην επηρεάζει συνολικά την ασφάλεια του συστήματος.

Τα πρωτόκολλα Group Key Agreement πρέπει επίσης να προσφέρουν αυθεντικοποίηση των συμμετεχόντων. Κάθε κόμβος που συμμετέχει στη διαδικασία συμφωνίας κλειδιού πρέπει να μπορεί να αποδείξει την ταυτότητά του, ώστε να αποτρέπονται επιθέσεις πλαστοπροσωπίας. Η αυθεντικοποίηση μπορεί να επιτευχθεί μέσω ψηφιακών υπογραφών, πιστοποιητικών ή μηχανισμών βασισμένων σε ταυτότητες.

Τέλος, ιδιαίτερη σημασία έχει η αποδοτικότητα του πρωτοκόλλου. Καθώς ο αριθμός των συμμετεχόντων αυξάνεται, το πρωτόκολλο πρέπει να παραμένει πρακτικά εφαρμόσιμο ως προς τον αριθμό των μηνυμάτων, τον χρόνο υπολογισμού και τη συνολική κατανάλωση πόρων. Η επεκτασιμότητα αποτελεί κρίσιμη ιδιότητα για την εφαρμογή τέτοιων πρωτοκόλλων σε πραγματικά κατανεμημένα συστήματα και σε περιβάλλοντα blockchain.

\section{Κεντρικοποιημένες Προσεγγίσεις}

Στα κεντρικοποιημένα πρωτόκολλα, ένας κεντρικός εξυπηρετητής ή διαχειριστής ομάδας (Group Controller) είναι υπεύθυνος για τη δημιουργία και διανομή του κλειδιού σε όλους τους συμμετέχοντες.

Έστω ένας controller $C$ και συμμετέχοντες $P_1, \dots, P_n$. Ο $C$ παράγει ένα μυστικό κλειδί $K$ και το διανέμει σε κάθε $P_i$ μέσω ασφαλούς καναλιού ή μέσω κρυπτογράφησης με δημόσια κλειδιά.

Παρότι απλά στην υλοποίηση, τα πρωτόκολλα αυτά παρουσιάζουν πρόβλημα single point of failure και περιορισμένη κλιμάκωση.

\section{Κατανεμημένες Προσεγγίσεις}

Στα κατανεμημένα πρωτόκολλα, δεν υπάρχει κεντρική αρχή. Όλοι οι συμμετέχοντες συνεισφέρουν ισότιμα στον υπολογισμό του τελικού κλειδιού.

Ένα γενικό μοντέλο βασίζεται σε επαναληπτικές εκθετικοποιήσεις της μορφής:
\[
K = g^{x_1 x_2 \cdots x_n},
\]
όπου κάθε $x_i$ είναι ιδιωτική τιμή του συμμετέχοντα $P_i$.

Η ασφάλεια βασίζεται σε παραλλαγές του Computational Diffie--Hellman problem.

\section{Δενδροειδείς Προσεγγίσεις (Tree-Based Approaches)}

Οι tree-based προσεγγίσεις οργανώνουν τους συμμετέχοντες σε ιεραρχική δομή δέντρου, μειώνοντας την πολυπλοκότητα επικοινωνίας.

Σε ένα δυαδικό δέντρο, κάθε εσωτερικός κόμβος αντιπροσωπεύει μερικό υπο-κλειδί, ενώ η ρίζα αντιστοιχεί στο τελικό κλειδί ομάδας.

Η πολυπλοκότητα μειώνεται από $O(n)$ σε $O(\log n)$ ως προς τον αριθμό των απαιτούμενων βημάτων επανακλειδώματος.

\section{Pairing-Based Group Key Agreement}

Τα πρωτόκολλα που βασίζονται σε διγραμμικές ζευγοποιήσεις επιτρέπουν αποδοτικές κατασκευές group key agreement με χρήση της απεικόνισης:
\[
e: G_1 \times G_2 \rightarrow G_T.
\]

Ένα τυπικό σχήμα επιτρέπει σε κάθε συμμετέχοντα $P_i$ με μυστικό $x_i$ να συμβάλει στο τελικό κλειδί μέσω εκφράσεων της μορφής:
\[
K = e(g,g)^{x_1 x_2 \cdots x_n}.
\]

Τα pairing-based πρωτόκολλα προσφέρουν αποδοτικές λύσεις σε σενάρια πολλαπλών συμμετεχόντων, αλλά αυξάνουν το υπολογιστικό κόστος σε σχέση με κλασικά DH-based συστήματα.

\section{Σύγκριση Προσεγγίσεων Group Key Agreement}

Οι διαφορετικές προσεγγίσεις ομαδικής συμφωνίας κλειδιού παρουσιάζουν διαφορετικά χαρακτηριστικά ως προς την ασφάλεια, την αποδοτικότητα και την καταλληλότητά τους για δυναμικά περιβάλλοντα. Οι κεντρικοποιημένες προσεγγίσεις βασίζονται συνήθως σε έναν έμπιστο διαχειριστή, ο οποίος αναλαμβάνει τη δημιουργία και διανομή του ομαδικού κλειδιού. Το βασικό τους πλεονέκτημα είναι η απλότητα σχεδίασης και υλοποίησης, καθώς τα μέλη δεν χρειάζεται να εκτελέσουν πολύπλοκες διαδικασίες συμφωνίας μεταξύ τους.

Ωστόσο, οι κεντρικοποιημένες προσεγγίσεις εισάγουν ένα κρίσιμο σημείο αποτυχίας. Αν ο κεντρικός διαχειριστής παραβιαστεί ή καταστεί μη διαθέσιμος, ολόκληρη η ασφάλεια και η λειτουργικότητα του συστήματος επηρεάζεται. Επιπλέον, η ύπαρξη κεντρικού κόμβου έρχεται σε αντίθεση με τη φιλοσοφία των αποκεντρωμένων συστημάτων και των blockchain υποδομών.

Αντίθετα, οι κατανεμημένες προσεγγίσεις επιδιώκουν να εξαλείψουν την ανάγκη ύπαρξης ενός πλήρως έμπιστου κεντρικού φορέα. Σε αυτές, το τελικό κλειδί προκύπτει από τη συμβολή όλων των συμμετεχόντων. Το χαρακτηριστικό αυτό ενισχύει την ασφάλεια, καθώς κανένας μεμονωμένος κόμβος δεν μπορεί να καθορίσει μόνος του το τελικό κλειδί. Παράλληλα, η απουσία κεντρικού σημείου ελέγχου καθιστά τις κατανεμημένες προσεγγίσεις πιο κατάλληλες για αποκεντρωμένα περιβάλλοντα.

Οι δενδροειδείς προσεγγίσεις αποτελούν έναν ενδιάμεσο μηχανισμό που στοχεύει κυρίως στη βελτίωση της αποδοτικότητας. Οργανώνοντας τους συμμετέχοντες σε δενδροειδή δομή, η διαδικασία επανακλειδώματος μπορεί να περιοριστεί σε συγκεκριμένα τμήματα του δένδρου όταν ένα μέλος εισέρχεται ή αποχωρεί από την ομάδα. Έτσι μειώνεται το υπολογιστικό και επικοινωνιακό κόστος σε σύγκριση με προσεγγίσεις όπου κάθε αλλαγή επηρεάζει όλα τα μέλη.

Οι pairing-based προσεγγίσεις αξιοποιούν τις ιδιότητες των διγραμμικών απεικονίσεων για την κατασκευή πιο σύνθετων και αποδοτικών πρωτοκόλλων. Η δυνατότητα των bilinear pairings να συνδέουν στοιχεία διαφορετικών ομάδων επιτρέπει την υλοποίηση μηχανισμών αυθεντικοποίησης και παραγωγής κοινών μυστικών με μικρότερο αριθμό γύρων επικοινωνίας. Παρόλα αυτά, οι πράξεις pairing είναι υπολογιστικά ακριβότερες από απλές πράξεις σε ελλειπτικές καμπύλες, γεγονός που πρέπει να λαμβάνεται υπόψη κατά την υλοποίηση.

Στο πλαίσιο της παρούσας εργασίας, το BDGKA συνδυάζει χαρακτηριστικά δυναμικής ομαδικής συμφωνίας κλειδιού, pairing-based κρυπτογραφίας και blockchain υποδομής. Η χρήση blockchain προσθέτει ιδιότητες ιχνηλασιμότητας, ακεραιότητας και μη αποποίησης ευθύνης, ενώ οι διγραμμικές απεικονίσεις χρησιμοποιούνται για την ασφαλή παραγωγή του τελικού ομαδικού κλειδιού.


\section{Δυναμική Συμμετοχή (Dynamic Membership)}

Σε πραγματικά συστήματα, η ομάδα μεταβάλλεται δυναμικά με εισαγωγή και αποχώρηση μελών.

Κατά την είσοδο νέου μέλους απαιτείται \textit{join rekeying}, ενώ κατά την αποχώρηση απαιτείται \textit{leave rekeying} ώστε να διατηρείται η forward και backward secrecy.

Η αποτυχία επανακλειδώματος οδηγεί σε παραβίαση της ασφάλειας του συστήματος.

\section{Μηχανισμοί Επανακλειδώματος (Rekeying Mechanisms)}

Οι μηχανισμοί rekeying διασφαλίζουν ότι το μυστικό κλειδί ανανεώνεται μετά από κάθε αλλαγή στη σύνθεση της ομάδας.

Οι κύριες κατηγορίες είναι:
\begin{itemize}
    \item πλήρης επαναϋπολογισμός του κλειδιού,
    \item μερική ενημέρωση μέσω broadcast μηνυμάτων,
    \item ιεραρχική ανανέωση σε tree-based δομές.
\end{itemize}

Η επιλογή μηχανισμού επηρεάζει άμεσα την απόδοση και την ασφάλεια του πρωτοκόλλου.

\section{Κλασικά Πρωτόκολλα Ομαδικής Συμφωνίας Κλειδιού}

Η έρευνα στον τομέα της συμφωνίας ομαδικού κλειδιού ξεκίνησε ως επέκταση του πρωτοκόλλου Diffie--Hellman για περισσότερους από δύο συμμετέχοντες. Στόχος των πρωτοκόλλων αυτών είναι η δημιουργία ενός κοινού μυστικού κλειδιού μεταξύ πολλών χρηστών χωρίς την ύπαρξη κεντρικού διαχειριστή.

Ένα από τα πρώτα και σημαντικότερα πρωτόκολλα είναι το Burmester--Desmedt Group Key Agreement Protocol. Το πρωτόκολλο αυτό επιτρέπει σε όλους τους συμμετέχοντες να συμβάλουν ισότιμα στη δημιουργία του τελικού κλειδιού, απαιτώντας μικρό αριθμό γύρων επικοινωνίας και παρουσιάζοντας καλή επεκτασιμότητα.

Μία ακόμη σημαντική κατηγορία αποτελεί το Tree Group Diffie--Hellman (TGDH), το οποίο οργανώνει τους συμμετέχοντες σε δενδροειδή δομή. Η προσέγγιση αυτή επιτρέπει αποδοτικότερη διαχείριση δυναμικών αλλαγών στην ομάδα, καθώς η αποχώρηση ή η είσοδος ενός μέλους επηρεάζει μόνο ένα τμήμα του δένδρου.

Η εμφάνιση των bilinear pairings οδήγησε στην ανάπτυξη νέων pairing-based πρωτοκόλλων, όπως το πρωτόκολλο Joux και οι επεκτάσεις του για πολλαπλούς συμμετέχοντες. Τα πρωτόκολλα αυτά αξιοποιούν τις ιδιότητες των διγραμμικών απεικονίσεων ώστε να μειώσουν τον αριθμό των απαιτούμενων ανταλλαγών μηνυμάτων και να προσφέρουν πρόσθετες δυνατότητες αυθεντικοποίησης.

Τα σύγχρονα πρωτόκολλα Group Key Agreement βασίζονται συχνά σε ελλειπτικές καμπύλες και διγραμμικές απεικονίσεις, επιδιώκοντας υψηλότερο επίπεδο ασφάλειας και καλύτερη απόδοση σε περιβάλλοντα μεγάλης κλίμακας.

\section{Επιθέσεις σε Πρωτόκολλα Group Key Agreement}

Η ασφάλεια ενός πρωτοκόλλου συμφωνίας ομαδικού κλειδιού εξαρτάται από την ικανότητά του να προστατεύεται απέναντι σε διάφορες κατηγορίες επιθέσεων. Για τον λόγο αυτό, κατά τον σχεδιασμό ενός πρωτοκόλλου λαμβάνονται υπόψη διαφορετικά μοντέλα επιτιθέμενων και σενάρια παραβίασης.

Μία από τις συνηθέστερες επιθέσεις είναι η επίθεση επανάληψης (Replay Attack), κατά την οποία ένας επιτιθέμενος καταγράφει έγκυρα μηνύματα μιας προηγούμενης εκτέλεσης του πρωτοκόλλου και τα επαναμεταδίδει με στόχο την παραπλάνηση των συμμετεχόντων.

Μία ακόμη σημαντική κατηγορία είναι η επίθεση Man-in-the-Middle, όπου ο επιτιθέμενος παρεμβάλλεται μεταξύ των συμμετεχόντων και επιχειρεί να τροποποιήσει ή να αντικαταστήσει τα ανταλλασσόμενα μηνύματα χωρίς να γίνει αντιληπτός.

Επιπλέον, ιδιαίτερη σημασία έχει η προστασία απέναντι σε επιθέσεις πλαστοπροσωπίας (Impersonation Attacks), στις οποίες ένας κακόβουλος χρήστης προσπαθεί να παρουσιαστεί ως νόμιμο μέλος της ομάδας.

Στα δυναμικά πρωτόκολλα συμφωνίας κλειδιού εξετάζονται επίσης επιθέσεις συνωμοσίας (Collusion Attacks), όπου πρώην και τρέχοντα μέλη συνεργάζονται προκειμένου να αποκτήσουν πρόσβαση σε ομαδικά κλειδιά που δεν δικαιούνται να γνωρίζουν.

Η αντιμετώπιση των παραπάνω επιθέσεων επιτυγχάνεται μέσω μηχανισμών αυθεντικοποίησης, ψηφιακών υπογραφών, χρήσης χρονοσφραγίδων και κατάλληλων διαδικασιών επανακλειδώματος της ομάδας.

\section{Συμπεράσματα}

Τα πρωτόκολλα ομαδικής συμφωνίας κλειδιού αποτελούν κρίσιμο στοιχείο σε κατανεμημένα συστήματα ασφαλείας. Οι κεντρικοποιημένες προσεγγίσεις είναι απλές αλλά μη κλιμακώσιμες, ενώ οι κατανεμημένες και pairing-based λύσεις προσφέρουν μεγαλύτερη ευελιξία και ασφάλεια με αυξημένο υπολογιστικό κόστος.
\chapter{Τεχνολογία Blockchain}

\section{Εξέλιξη των Blockchain}

Η τεχνολογία blockchain αποτελεί μια κατανεμημένη δομή δεδομένων η οποία επιτρέπει την αμετάβλητη καταγραφή συναλλαγών χωρίς την ανάγκη κεντρικής αρχής εμπιστοσύνης. Η πρώτη πρακτική υλοποίηση εμφανίστηκε με το Bitcoin, εισάγοντας έναν μηχανισμό Proof of Work για την επίτευξη συναίνεσης σε ένα πλήρως αποκεντρωμένο δίκτυο.

Στη συνέχεια, η εξέλιξη των blockchain συστημάτων οδήγησε σε πιο γενικευμένες πλατφόρμες, όπως το Ethereum, οι οποίες υποστηρίζουν προγραμματιζόμενη λογική μέσω smart contracts, καθώς και σε permissioned συστήματα με αυξημένες απαιτήσεις απόδοσης και ελέγχου πρόσβασης.

\section{Δημόσια, Ιδιωτικά και Permissioned Blockchain}

Τα blockchain δίκτυα μπορούν να κατηγοριοποιηθούν με βάση τον τρόπο πρόσβασης, τη διαδικασία συμμετοχής των κόμβων και το μοντέλο εμπιστοσύνης που υιοθετούν. Η διάκριση αυτή είναι σημαντική, καθώς διαφορετικές κατηγορίες blockchain είναι κατάλληλες για διαφορετικά είδη εφαρμογών.

Στα δημόσια blockchain, οποιοσδήποτε χρήστης μπορεί να συμμετάσχει στο δίκτυο, να δημιουργήσει συναλλαγές και, ανάλογα με τον μηχανισμό συναίνεσης, να λάβει μέρος στη διαδικασία επικύρωσης. Παραδείγματα δημόσιων blockchain αποτελούν το Bitcoin και το Ethereum. Το βασικό τους πλεονέκτημα είναι ο υψηλός βαθμός αποκέντρωσης και η ανοικτή συμμετοχή. Ωστόσο, η πλήρης απουσία ελέγχου συμμετεχόντων οδηγεί συνήθως σε υψηλότερο κόστος συναίνεσης, αυξημένες καθυστερήσεις και περιορισμένη απόδοση.

Αντίθετα, στα ιδιωτικά blockchain η πρόσβαση στο δίκτυο ελέγχεται από έναν οργανισμό ή μία περιορισμένη ομάδα διαχειριστών. Οι συμμετέχοντες είναι γνωστοί εκ των προτέρων και η επικύρωση των συναλλαγών πραγματοποιείται από εξουσιοδοτημένους κόμβους. Η προσέγγιση αυτή προσφέρει καλύτερη απόδοση και μεγαλύτερο έλεγχο, αλλά περιορίζει τον βαθμό αποκέντρωσης.

Τα permissioned blockchain αποτελούν μία ειδική κατηγορία blockchain δικτύων, όπου οι συμμετέχοντες πρέπει να διαθέτουν κατάλληλα δικαιώματα πρόσβασης. Σε τέτοια δίκτυα, η ταυτότητα των κόμβων είναι γνωστή και ελέγχεται μέσω μηχανισμών πιστοποίησης. Το Hyperledger Fabric ανήκει σε αυτή την κατηγορία και είναι κατάλληλο για επιχειρησιακές εφαρμογές, όπου απαιτείται έλεγχος πρόσβασης, διαχείριση ταυτοτήτων και υψηλή απόδοση.

Η επιλογή permissioned blockchain είναι ιδιαίτερα σημαντική για την παρούσα εργασία, καθώς το πρωτόκολλο BDGKA εκτελείται σε περιβάλλον όπου οι συμμετέχοντες κόμβοι πρέπει να είναι γνωστοί και αυθεντικοποιημένοι. Με τον τρόπο αυτό, η υποδομή blockchain δεν λειτουργεί μόνο ως μηχανισμός αποθήκευσης δεδομένων, αλλά και ως μέσο ενίσχυσης της εμπιστοσύνης μεταξύ των συμμετεχόντων.

\section{Μηχανισμοί Συναίνεσης}

Οι μηχανισμοί συναίνεσης αποτελούν βασικό στοιχείο κάθε blockchain συστήματος, καθώς καθορίζουν τον τρόπο με τον οποίο οι κόμβοι του δικτύου συμφωνούν για την εγκυρότητα και τη σειρά των συναλλαγών. Χωρίς έναν τέτοιο μηχανισμό, δεν θα ήταν δυνατό να διατηρηθεί μία κοινή και συνεπής κατάσταση του ledger μεταξύ των διαφορετικών κόμβων.

Στα δημόσια blockchain χρησιμοποιούνται συχνά μηχανισμοί όπως το Proof of Work και το Proof of Stake. Το Proof of Work βασίζεται στην επίλυση υπολογιστικά δύσκολων προβλημάτων, απαιτώντας σημαντική κατανάλωση υπολογιστικών πόρων. Αντίθετα, το Proof of Stake επιλέγει επικυρωτές με βάση το ποσοστό συμμετοχής τους στο δίκτυο, μειώνοντας την ενεργειακή κατανάλωση σε σχέση με το Proof of Work.

Σε permissioned blockchain δίκτυα, όπως το Hyperledger Fabric, η συναίνεση μπορεί να επιτευχθεί με πιο αποδοτικούς μηχανισμούς, επειδή οι συμμετέχοντες είναι γνωστοί και πιστοποιημένοι. Έτσι δεν απαιτούνται ενεργοβόροι μηχανισμοί όπως το Proof of Work. Αντίθετα, μπορούν να χρησιμοποιηθούν μηχανισμοί όπως το Raft ή άλλες μορφές ordering service, οι οποίες προσφέρουν καλύτερη απόδοση και μικρότερη καθυστέρηση.

Η επιλογή του κατάλληλου μηχανισμού συναίνεσης επηρεάζει άμεσα την απόδοση του συστήματος. Σε εφαρμογές όπου απαιτείται γρήγορη καταχώριση δεδομένων, όπως στην περίπτωση ενός πρωτοκόλλου συμφωνίας κλειδιού, η καθυστέρηση συναίνεσης μπορεί να επηρεάσει τον συνολικό χρόνο εκτέλεσης. Για τον λόγο αυτό, η χρήση Hyperledger Fabric είναι κατάλληλη, καθώς διαχωρίζει τη διαδικασία εκτέλεσης συναλλαγών, επικύρωσης και ταξινόμησης, προσφέροντας μεγαλύτερη ευελιξία.

\section{Smart Contracts}

Τα έξυπνα συμβόλαια αποτελούν προγράμματα τα οποία εκτελούνται πάνω σε ένα blockchain δίκτυο και καθορίζουν τη λογική διαχείρισης των δεδομένων. Μέσω αυτών, οι χρήστες μπορούν να αλληλεπιδρούν με το ledger με ελεγχόμενο και προκαθορισμένο τρόπο.

Σε ένα blockchain σύστημα, το smart contract καθορίζει ποιες λειτουργίες επιτρέπονται, ποια δεδομένα μπορούν να καταχωριστούν και υπό ποιες προϋποθέσεις μπορεί να τροποποιηθεί η κατάσταση του ledger. Με τον τρόπο αυτό, η επιχειρησιακή λογική της εφαρμογής μεταφέρεται στο ίδιο το blockchain δίκτυο.

Στο Hyperledger Fabric, τα smart contracts υλοποιούνται με τη μορφή chaincode. Το chaincode εγκαθίσταται στους peers του δικτύου και εκτελείται όταν ένας client υποβάλλει μία συναλλαγή. Η εκτέλεση του chaincode παράγει αποτελέσματα τα οποία στη συνέχεια επικυρώνονται και καταχωρίζονται στο ledger.

Στην παρούσα εργασία, το chaincode χρησιμοποιείται για την καταγραφή δεδομένων που σχετίζονται με την εκτέλεση του πρωτοκόλλου BDGKA. Τέτοια δεδομένα περιλαμβάνουν δημόσιες παραμέτρους, δημόσιες συνεισφορές κόμβων, υπογραφές και πληροφορίες που είναι απαραίτητες για την επαλήθευση της διαδικασίας. Με τον τρόπο αυτό, το blockchain λειτουργεί ως αξιόπιστο και αμετάβλητο μέσο καταγραφής των κρίσιμων βημάτων του πρωτοκόλλου.

\section{Identity Management}

Η διαχείριση ταυτοτήτων αποτελεί κρίσιμο ζήτημα σε κάθε blockchain σύστημα, ιδιαίτερα όταν το δίκτυο δεν είναι δημόσιο αλλά permissioned. Σε τέτοια περιβάλλοντα, κάθε συμμετέχων πρέπει να διαθέτει μία επαληθεύσιμη ταυτότητα, ώστε να είναι δυνατό να ελεγχθεί ποιος εκτελεί κάθε ενέργεια.

Στα δημόσια blockchain, η ταυτότητα ενός χρήστη συνδέεται συνήθως με ένα ζεύγος δημόσιου και ιδιωτικού κλειδιού. Η διεύθυνση του χρήστη προκύπτει από το δημόσιο κλειδί, ενώ το ιδιωτικό κλειδί χρησιμοποιείται για την υπογραφή συναλλαγών. Το μοντέλο αυτό προσφέρει ψευδωνυμία, αλλά δεν παρέχει απαραίτητα άμεση σύνδεση με πραγματικές οργανωτικές ταυτότητες.

Αντίθετα, σε permissioned blockchain όπως το Hyperledger Fabric, οι ταυτότητες βασίζονται σε ψηφιακά πιστοποιητικά. Κάθε οργανισμός διαθέτει δική του Certificate Authority, η οποία εκδίδει πιστοποιητικά για τους χρήστες και τους κόμβους του δικτύου. Τα πιστοποιητικά αυτά χρησιμοποιούνται για την αυθεντικοποίηση των συμμετεχόντων και τον έλεγχο των δικαιωμάτων πρόσβασης.

Η ύπαρξη μηχανισμού διαχείρισης ταυτοτήτων είναι ιδιαίτερα σημαντική για την υλοποίηση ενός πρωτοκόλλου συμφωνίας κλειδιού. Οι κόμβοι που συμμετέχουν στη διαδικασία πρέπει να είναι γνωστοί και να μπορούν να αποδείξουν την ταυτότητά τους. Έτσι αποτρέπονται επιθέσεις πλαστοπροσωπίας και διασφαλίζεται ότι μόνο εξουσιοδοτημένα μέλη μπορούν να συμμετέχουν στην παραγωγή του ομαδικού κλειδιού.


\subsection{Proof of Work (PoW)}

Το Proof of Work απαιτεί από τους miners να επιλύσουν ένα υπολογιστικά δύσκολο πρόβλημα της μορφής:
\[
H(B \parallel nonce) < T,
\]
όπου $H$ είναι μια κρυπτογραφική συνάρτηση κατακερματισμού και $T$ το όριο δυσκολίας.

Η ασφάλεια βασίζεται στο υψηλό υπολογιστικό κόστος αναδημιουργίας της αλυσίδας.

\subsection{Proof of Stake (PoS)}

Στο Proof of Stake, η επιλογή του δημιουργού ενός block εξαρτάται από το ποσοστό συμμετοχής (stake) του κόμβου στο δίκτυο. Η πιθανότητα επιλογής είναι ανάλογη του stake, μειώνοντας σημαντικά την ενεργειακή κατανάλωση σε σχέση με το PoW.

\subsection{Practical Byzantine Fault Tolerance (PBFT)}

Το PBFT είναι ένα σύστημα συναίνεσης σχεδιασμένο για permissioned δίκτυα, το οποίο αντέχει την παρουσία κακόβουλων κόμβων μέχρι ένα όριο $f$, όπου το σύνολο των κόμβων ικανοποιεί:
\[
n \ge 3f + 1.
\]

Το πρωτόκολλο λειτουργεί μέσω φάσεων επικοινωνίας μεταξύ primary και backup nodes, εξασφαλίζοντας συμφωνία ακόμη και υπό Byzantine αποτυχίες.

\subsection{Raft}

Το Raft είναι ένας αλγόριθμος συναίνεσης σχεδιασμένος για απλότητα και κατανοησιμότητα. Βασίζεται στην εκλογή leader και στην αναπαραγωγή log entries στους follower nodes.

Σε αντίθεση με το PBFT, το Raft δεν είναι Byzantine fault tolerant, αλλά παρέχει ισχυρή συνέπεια σε περιβάλλοντα όπου οι κόμβοι θεωρούνται αξιόπιστοι.


\section{Identity Management}

Η διαχείριση ταυτότητας σε blockchain συστήματα στοχεύει στην αποκέντρωση της ψηφιακής ταυτότητας, μειώνοντας την εξάρτηση από κεντρικούς παρόχους.

Τα Decentralized Identity (DID) συστήματα επιτρέπουν στους χρήστες να ελέγχουν τα ίδια τα κρυπτογραφικά τους αναγνωριστικά μέσω δημόσιων κλειδιών και αποδείξεων ταυτότητας.

Η βασική αρχή είναι ότι η ταυτότητα ενός χρήστη συνδέεται με ένα ζεύγος κλειδιών $(sk, pk)$, όπου:
\[
pk = sk \cdot G,
\]
και οι συναλλαγές ή πιστοποιήσεις επαληθεύονται μέσω ψηφιακών υπογραφών.

Η ενσωμάτωση blockchain σε identity management ενισχύει την ακεραιότητα, την ιχνηλασιμότητα και την ανθεκτικότητα σε παραποίηση δεδομένων. 

\section{Δομή ενός Block}

Το blockchain αποτελείται από μία αλληλουχία blocks τα οποία συνδέονται μεταξύ τους μέσω κρυπτογραφικών συναρτήσεων κατακερματισμού. Κάθε block περιέχει ένα σύνολο συναλλαγών ή δεδομένων καθώς και πληροφορίες που επιτρέπουν την επαλήθευση της ακεραιότητάς του.

Ένα τυπικό block αποτελείται από δύο κύρια μέρη: την επικεφαλίδα (block header) και το σώμα (block body). Η επικεφαλίδα περιλαμβάνει πληροφορίες όπως το hash του προηγούμενου block, τη χρονοσφραγίδα δημιουργίας, τον μηχανισμό συναίνεσης και τη ρίζα Merkle. Το σώμα περιέχει το σύνολο των συναλλαγών ή εγγραφών που αποθηκεύονται στο block.

Η ύπαρξη του hash του προηγούμενου block δημιουργεί μία αλυσίδα εξαρτήσεων μεταξύ όλων των blocks. Ως αποτέλεσμα, οποιαδήποτε τροποποίηση σε παλαιότερο block μεταβάλλει το αντίστοιχο hash και καθιστά άμεσα ανιχνεύσιμη την παραποίηση των δεδομένων.

\section{Merkle Trees}

Τα Merkle Trees αποτελούν ειδικές δενδροειδείς δομές δεδομένων που χρησιμοποιούνται ευρέως στα blockchain συστήματα για την αποδοτική επαλήθευση της ακεραιότητας μεγάλου όγκου δεδομένων.

Κάθε φύλλο του δένδρου αντιστοιχεί στο αποτέλεσμα μιας συνάρτησης κατακερματισμού που εφαρμόζεται σε μία συναλλαγή. Στη συνέχεια, τα γειτονικά hashes συνδυάζονται και κατακερματίζονται εκ νέου, μέχρι να παραχθεί μία μοναδική τιμή η οποία ονομάζεται Merkle Root.

Η τιμή αυτή αποθηκεύεται στην επικεφαλίδα του block και λειτουργεί ως κρυπτογραφικό αποτύπωμα όλων των συναλλαγών που περιέχει. Με τον τρόπο αυτό καθίσταται δυνατή η αποδοτική επαλήθευση συγκεκριμένων συναλλαγών χωρίς να απαιτείται η ανάγνωση ολόκληρου του block.

Η χρήση των Merkle Trees μειώνει σημαντικά το κόστος αποθήκευσης και επικοινωνίας, ενώ παράλληλα ενισχύει την ακεραιότητα των δεδομένων που διατηρούνται στο blockchain.

\section{Ασφάλεια Blockchain}

Η ασφάλεια αποτελεί μία από τις σημαντικότερες ιδιότητες των blockchain συστημάτων. Η προστασία των δεδομένων επιτυγχάνεται μέσω του συνδυασμού κρυπτογραφικών τεχνικών, μηχανισμών συναίνεσης και κατανεμημένης αποθήκευσης.

Μία γνωστή κατηγορία απειλών είναι οι επιθέσεις 51\%, κατά τις οποίες ένας επιτιθέμενος αποκτά τον έλεγχο της πλειονότητας των υπολογιστικών ή επικυρωτικών πόρων του δικτύου. Σε τέτοια περίπτωση μπορεί να επιχειρήσει την αναδιοργάνωση της αλυσίδας και τη διπλή δαπάνη συναλλαγών.

Επιπλέον, συναντώνται επιθέσεις Sybil, κατά τις οποίες ένας χρήστης δημιουργεί μεγάλο αριθμό ψευδών ταυτοτήτων με σκοπό να επηρεάσει τη λειτουργία του δικτύου. Παράλληλα, ιδιαίτερη προσοχή απαιτείται στην ασφάλεια των έξυπνων συμβολαίων, καθώς σφάλματα στον πηγαίο κώδικα μπορούν να οδηγήσουν σε σοβαρές παραβιάσεις ασφαλείας.

Στα permissioned blockchain δίκτυα, όπως το Hyperledger Fabric, οι κίνδυνοι αυτοί περιορίζονται μέσω μηχανισμών ελέγχου ταυτότητας, ψηφιακών πιστοποιητικών και αυστηρών πολιτικών πρόσβασης.

\section{Blockchain και Διαχείριση Κλειδιών}

Η διαχείριση κρυπτογραφικών κλειδιών αποτελεί κρίσιμο ζήτημα σε κατανεμημένα συστήματα. Η χρήση blockchain προσφέρει έναν ασφαλή και αμετάβλητο μηχανισμό αποθήκευσης πληροφοριών που σχετίζονται με τη διαδικασία δημιουργίας και διαχείρισης κλειδιών.

Στο πλαίσιο των πρωτοκόλλων Group Key Agreement, το blockchain μπορεί να χρησιμοποιηθεί για την καταγραφή δημοσίων παραμέτρων, ψηφιακών υπογραφών και στοιχείων επαλήθευσης. Με τον τρόπο αυτό παρέχεται πλήρης ιχνηλασιμότητα όλων των ενεργειών που πραγματοποιούνται κατά την εκτέλεση του πρωτοκόλλου.

Επιπλέον, η αμεταβλητότητα του blockchain επιτρέπει την αποτροπή μη εξουσιοδοτημένων τροποποιήσεων, ενώ η αποκεντρωμένη φύση του εξαλείφει την ανάγκη ύπαρξης ενός κεντρικού σημείου εμπιστοσύνης.

Για τους λόγους αυτούς, η ενσωμάτωση τεχνολογιών blockchain σε πρωτόκολλα συμφωνίας κλειδιού αποτελεί μία ιδιαίτερα ελκυστική προσέγγιση για σύγχρονα κατανεμημένα συστήματα.

\chapter{Hyperledger Fabric}

\section{Εισαγωγή}

Το Hyperledger Fabric αποτελεί μια permissioned blockchain πλατφόρμα γενικού σκοπού, σχεδιασμένη για επιχειρησιακές εφαρμογές με υψηλές απαιτήσεις σε απόδοση, εμπιστευτικότητα και διαχείριση ταυτότητας. Σε αντίθεση με τα δημόσια blockchain, το Fabric υποστηρίζει ελεγχόμενη συμμετοχή κόμβων και ευέλικτες πολιτικές συναίνεσης και πρόσβασης.

\section{Αρχιτεκτονική Hyperledger Fabric}

Η αρχιτεκτονική του Hyperledger Fabric βασίζεται σε μια modular σχεδίαση, όπου τα επιμέρους συστατικά του δικτύου διαχωρίζονται σε διακριτούς ρόλους. Το δίκτυο αποτελείται από οργανισμούς, κόμβους (peers), υπηρεσίες ordering και μηχανισμούς διαχείρισης ταυτότητας.

Η βασική αρχή σχεδίασης είναι ο διαχωρισμός των φάσεων εκτέλεσης, ordering και επικύρωσης συναλλαγών, επιτρέποντας υψηλή κλιμάκωση και παραλληλισμό.

\section{Συστατικά του Fabric}

\subsection{Peers}

Οι peer nodes αποτελούν τους βασικούς συμμετέχοντες του δικτύου. Κάθε peer διατηρεί ένα αντίγραφο του ledger και εκτελεί smart contracts (chaincode).

Οι peers διακρίνονται σε endorsing peers και committing peers, ανάλογα με τον ρόλο τους στην επεξεργασία συναλλαγών.

\subsection{Orderers}

Οι orderer nodes είναι υπεύθυνοι για τη συνολική διάταξη των συναλλαγών στο δίκτυο. Συλλέγουν συναλλαγές από τους clients και τις οργανώνουν σε blocks, τα οποία στη συνέχεια διανέμονται στους peers.

Η λειτουργία τους είναι ανεξάρτητη από την εκτέλεση smart contracts, εξασφαλίζοντας διαχωρισμό καθηκόντων.

\subsection{MSP (Membership Service Provider)}

Το MSP αποτελεί τον μηχανισμό διαχείρισης ταυτότητας στο Fabric. Ορίζει τις πολιτικές ταυτοποίησης και εξουσιοδότησης των συμμετεχόντων στο δίκτυο.

Κάθε οργανισμός στο δίκτυο διαθέτει το δικό του MSP, το οποίο καθορίζει ποιοι χρήστες και κόμβοι θεωρούνται έγκυροι.

\subsection{Certificate Authorities}

Οι Certificate Authorities (CA) είναι υπεύθυνες για την έκδοση, ανανέωση και ανάκληση ψηφιακών πιστοποιητικών. Τα πιστοποιητικά αυτά βασίζονται συνήθως σε υποδομή δημόσιου κλειδιού (PKI) με χρήση ελλειπτικών καμπυλών.

Οι CA αποτελούν θεμέλιο για την αυθεντικοποίηση και την εμπιστοσύνη στο δίκτυο.

\section{Channels}

Τα channels στο Hyperledger Fabric επιτρέπουν τη δημιουργία απομονωμένων υπο-δικτύων εντός του ίδιου blockchain συστήματος. Κάθε channel διαθέτει το δικό του ledger και πολιτικές πρόσβασης.

Αυτό επιτρέπει την ιδιωτικότητα των δεδομένων μεταξύ υποομάδων συμμετεχόντων χωρίς να απαιτείται ξεχωριστό blockchain.

\section{Δομή του Ledger}

Το ledger στο Fabric αποτελείται από δύο βασικά μέρη:

\begin{itemize}
    \item το blockchain, το οποίο περιέχει την αμετάβλητη αλυσίδα blocks,
    \item το world state, το οποίο αποτελεί τη βάση δεδομένων τρέχουσας κατάστασης.
\end{itemize}

Το world state υλοποιείται συνήθως μέσω key-value αποθήκης, όπως LevelDB ή CouchDB.

\section{Endorsement Policies}

Οι endorsement policies καθορίζουν ποιοι peers πρέπει να υπογράψουν μια συναλλαγή ώστε να θεωρηθεί έγκυρη.

Τυπικά, μια πολιτική μπορεί να οριστεί ως:
\[
E = (P_1 \wedge P_2) \vee P_3,
\]
όπου $P_i$ αντιστοιχούν σε οργανισμούς ή peers.

Οι πολιτικές αυτές ενισχύουν την εμπιστοσύνη χωρίς την ανάγκη πλήρους ομοφωνίας.

\section{Chaincode}

Το chaincode αποτελεί την υλοποίηση των smart contracts στο Hyperledger Fabric. Εκτελείται από τους peers και καθορίζει τη λογική των συναλλαγών.

Τυπικά, ένα chaincode ορίζεται ως συνάρτηση μετάβασης κατάστασης:
\[
f: S \times T \rightarrow S,
\]
όπου $S$ είναι το state και $T$ οι συναλλαγές.

Η εκτέλεση του chaincode είναι deterministic, ώστε όλοι οι peers να καταλήγουν στο ίδιο αποτέλεσμα.

\section{Private Data Collections}

Οι private data collections επιτρέπουν την αποθήκευση ευαίσθητων δεδομένων που είναι ορατά μόνο σε υποσύνολο των οργανισμών του δικτύου.

Τα δεδομένα αποθηκεύονται τοπικά στους authorized peers, ενώ στο blockchain καταγράφεται μόνο hash για επαλήθευση ακεραιότητας.

\section{Μοντέλο Ασφάλειας του Fabric}

Το μοντέλο ασφάλειας του Hyperledger Fabric βασίζεται σε τρία επίπεδα:

\begin{itemize}
    \item \textbf{Ταυτοποίηση:} μέσω MSP και PKI υποδομών,
    \item \textbf{Εξουσιοδότηση:} μέσω endorsement policies και ACLs,
    \item \textbf{Ακεραιότητα:} μέσω ordering service και κρυπτογραφικών hashes.
\end{itemize}

Η αρχιτεκτονική του Fabric επιτρέπει την αποφυγή των περιορισμών των δημόσιων blockchain, προσφέροντας υψηλή απόδοση και λεπτομερή έλεγχο πρόσβασης σε επιχειρησιακά περιβάλλοντα.
\chapter{Άρθρο Υλοποίησης}

\section{Μοντέλο Συστήματος}

Το προτεινόμενο πρωτόκολλο σχεδιάστηκε για την ασφαλή δημιουργία και διαχείριση ομαδικού κλειδιού σε ένα αποκεντρωμένο περιβάλλον επικοινωνίας. Το σύστημα αποτελείται από ένα σύνολο χρηστών που επιθυμούν να δημιουργήσουν ένα κοινό μυστικό κλειδί χωρίς να απαιτείται η συνεχής παρουσία μιας κεντρικής αρχής κατά τη διάρκεια της εκτέλεσης του πρωτοκόλλου.

Η αρχιτεκτονική του συστήματος περιλαμβάνει έναν κόμβο αρχικοποίησης, ο οποίος αναφέρεται ως \textit{Key Generation Center (KGC)}, καθώς και ένα σύνολο χρηστών:

\[
U = \{u_1,u_2,\ldots,u_n\}
\]

όπου $n$ είναι ο συνολικός αριθμός των συμμετεχόντων στην ομάδα.

Ο ρόλος του $KGC$ περιορίζεται αποκλειστικά στη φάση εγκατάστασης του συστήματος. Συγκεκριμένα, ο $KGC$ είναι υπεύθυνος για:

\begin{itemize}
\item τη δημιουργία των δημόσιων παραμέτρων του συστήματος,
\item τον ορισμό των κρυπτογραφικών ομάδων που χρησιμοποιούνται,
\item την επιλογή των συναρτήσεων κατακερματισμού,
\item την αρχική εγγραφή των χρηστών,
\item τη διανομή των απαραίτητων στοιχείων εκκίνησης.
\end{itemize}

Μετά την ολοκλήρωση της διαδικασίας αυτής, ο $KGC$ δεν συμμετέχει στη δημιουργία του ομαδικού κλειδιού ούτε παρεμβαίνει στις επικοινωνίες μεταξύ των χρηστών. Ως αποτέλεσμα, το προτεινόμενο σχήμα δεν εξαρτάται από μία μόνιμα διαθέσιμη κεντρική αρχή, μειώνοντας το πρόβλημα του single point of failure.

Οι χρήστες θεωρούνται ισότιμοι συμμετέχοντες στο πρωτόκολλο και συνεισφέρουν όλοι στη διαδικασία παραγωγής του τελικού ομαδικού κλειδιού. Η συμμετοχή κάθε χρήστη είναι απαραίτητη για την παραγωγή του τελικού μυστικού, γεγονός που προσδίδει στο πρωτόκολλο χαρακτηριστικά contributory group key agreement.

Το υποκείμενο δίκτυο επικοινωνίας θεωρείται μη αξιόπιστο. Ένας επιτιθέμενος μπορεί να παρακολουθεί, να καταγράφει, να τροποποιεί ή να επαναμεταδίδει μηνύματα τα οποία ανταλλάσσονται μεταξύ των κόμβων. Ωστόσο, θεωρείται ότι δεν μπορεί να παραβιάσει τις βασικές υπολογιστικές υποθέσεις πάνω στις οποίες στηρίζεται η ασφάλεια του συστήματος, όπως η δυσκολία επίλυσης του προβλήματος Bilinear Diffie--Hellman.

Για την ενίσχυση της διαφάνειας και της επαληθευσιμότητας, το πρωτόκολλο ενσωματώνει ένα permissioned blockchain βασισμένο στο Hyperledger Fabric. Το blockchain λειτουργεί ως αμετάβλητος μηχανισμός καταγραφής των κρίσιμων γεγονότων της εκτέλεσης του πρωτοκόλλου.

Συγκεκριμένα, στο καθολικό καταγράφονται:

\begin{itemize}
\item τα δημόσια κλειδιά των συμμετεχόντων,
\item οι δημόσιες τυχαίες συνεισφορές των χρηστών,
\item οι ψηφιακές υπογραφές που παράγονται κατά τη διάρκεια του πρωτοκόλλου,
\item οι χρονικές σφραγίδες των ενεργειών,
\item μεταδεδομένα απαραίτητα για την επαλήθευση της εκτέλεσης.
\end{itemize}

Η χρήση του Hyperledger Fabric επιτρέπει τον έλεγχο πρόσβασης στους συμμετέχοντες μέσω πιστοποιητικών και πολιτικών εξουσιοδότησης, ενώ παράλληλα εξασφαλίζει ότι τα καταγεγραμμένα δεδομένα δεν μπορούν να αλλοιωθούν χωρίς να γίνει αντιληπτό από το σύνολο του δικτύου.

Από κρυπτογραφικής πλευράς, το πρωτόκολλο βασίζεται σε διγραμμικές ζευγοποιήσεις (bilinear pairings) ορισμένες πάνω σε κυκλικές ομάδες πρώτης τάξης. Οι ζευγοποιήσεις αυτές επιτρέπουν την κατασκευή μηχανισμών επαλήθευσης και συμφωνίας κλειδιού που δεν είναι εφικτοί με τα κλασικά πρωτόκολλα Diffie--Hellman.

Η βασική υπόθεση ασφάλειας του συστήματος είναι ότι ένας αντίπαλος δεν μπορεί να επιλύσει αποδοτικά το πρόβλημα Bilinear Diffie--Hellman (BDH), ακόμη και αν διαθέτει πλήρη γνώση όλων των δημόσιων παραμέτρων και των μηνυμάτων που ανταλλάσσονται κατά τη διάρκεια του πρωτοκόλλου.

Υπό τις παραπάνω παραδοχές, το προτεινόμενο μοντέλο συστήματος παρέχει ένα κατάλληλο περιβάλλον για την ασφαλή δημιουργία κοινού ομαδικού κλειδιού, συνδυάζοντας τις ιδιότητες των bilinear pairings με τους μηχανισμούς ακεραιότητας και ιχνηλασιμότητας που προσφέρει το Hyperledger Fabric.

\section{Κρυπτογραφική Αρχικοποίηση}

Η φάση αρχικοποίησης αποτελεί το θεμέλιο του προτεινόμενου πρωτοκόλλου, καθώς καθορίζει το μαθηματικό περιβάλλον μέσα στο οποίο θα πραγματοποιηθούν οι κρυπτογραφικές πράξεις. Η διαδικασία εκτελείται από τον κόμβο $KGC$ πριν από την ένταξη των χρηστών στο σύστημα και ολοκληρώνεται μία μόνο φορά κατά τη δημιουργία του δικτύου.

Στόχος της φάσης αυτής είναι η δημιουργία ενός συνόλου δημόσιων παραμέτρων οι οποίες θα χρησιμοποιηθούν από όλους τους συμμετέχοντες κατά την εκτέλεση του πρωτοκόλλου συμφωνίας ομαδικού κλειδιού.

Αρχικά, ο $KGC$ επιλέγει δύο κυκλικές ομάδες πρώτης τάξης $G_1$ και $G_2$, οι οποίες έχουν κοινή τάξη ίση με έναν μεγάλο πρώτο αριθμό $q$.

\[
|G_1| = |G_2| = q
\]

Η ομάδα $G_1$ χρησιμοποιείται για την αναπαράσταση σημείων ελλειπτικής καμπύλης, ενώ η ομάδα $G_2$ χρησιμοποιείται ως ομάδα στόχος της διγραμμικής απεικόνισης.

Στη συνέχεια επιλέγεται ένας γεννήτορας

\[
g \in G_1
\]

τέτοιος ώστε κάθε στοιχείο της ομάδας να μπορεί να παραχθεί μέσω επαναλαμβανόμενων πράξεων του $g$.

Πάνω στις ομάδες αυτές ορίζεται μια διγραμμική απεικόνιση

\[
e : G_1 \times G_1 \rightarrow G_2.
\]

Η απεικόνιση αυτή πρέπει να ικανοποιεί τρεις θεμελιώδεις ιδιότητες.

Η πρώτη ιδιότητα είναι η διγραμμικότητα (bilinearity). Για κάθε $P,Q \in G_1$ και για κάθε $a,b \in \mathbb{Z}_q$ ισχύει:

\[
e(aP,bQ)=e(P,Q)^{ab}.
\]

Η ιδιότητα αυτή αποτελεί τον βασικό μηχανισμό μέσω του οποίου επιτυγχάνεται η παραγωγή του κοινού ομαδικού κλειδιού.

Η δεύτερη ιδιότητα είναι ο μη εκφυλισμός (non-degeneracy). Συγκεκριμένα πρέπει να ισχύει:

\[
e(g,g)\neq 1_{G_2}.
\]

Η απαίτηση αυτή διασφαλίζει ότι η ζευγοποίηση δεν καταρρέει σε τετριμμένες τιμές και συνεπώς διατηρεί την κρυπτογραφική της χρησιμότητα.

Η τρίτη ιδιότητα είναι η υπολογισιμότητα (computability), σύμφωνα με την οποία υπάρχει αποδοτικός αλγόριθμος υπολογισμού της τιμής

\[
e(P,Q)
\]

για οποιαδήποτε σημεία $P,Q \in G_1$.

Μετά τον ορισμό της ζευγοποίησης, ο $KGC$ επιλέγει δύο κρυπτογραφικές συναρτήσεις κατακερματισμού.

Η πρώτη συνάρτηση χρησιμοποιείται για τη μετατροπή ταυτοτήτων ή συμβολοσειρών σε στοιχεία της ομάδας $G_1$:

\[
H_1:\{0,1\}^{*}\rightarrow G_1.
\]

Η συνάρτηση αυτή μοντελοποιείται ως random oracle και χρησιμοποιείται για τη χαρτογράφηση δεδομένων σε σημεία της ελλειπτικής καμπύλης.

Η δεύτερη συνάρτηση κατακερματισμού ορίζεται ως:

\[
H_2:\{0,1\}^{*}\rightarrow \mathbb{Z}_q^{*}.
\]

Η συνάρτηση αυτή χρησιμοποιείται για τη δημιουργία τιμών δέσμευσης και για την παραγωγή παραμέτρων επαλήθευσης κατά τη διάρκεια του πρωτοκόλλου.

Στη συνέχεια ορίζεται το σύνολο των δημόσιων παραμέτρων του συστήματος:

\[
params=
(G_1,G_2,q,g,e,H_1,H_2).
\]

Οι παράμετροι αυτές δημοσιεύονται σε όλους τους συμμετέχοντες και θεωρούνται κοινή γνώση.

Αξίζει να σημειωθεί ότι οι δημόσιες παράμετροι δεν περιέχουν καμία μυστική πληροφορία. Η αποκάλυψή τους δεν επηρεάζει την ασφάλεια του συστήματος, καθώς η προστασία βασίζεται στις υπολογιστικές υποθέσεις δυσκολίας των υποκείμενων μαθηματικών προβλημάτων.

Η ασφάλεια του προτεινόμενου πρωτοκόλλου εξαρτάται κυρίως από τη δυσκολία επίλυσης του προβλήματος Bilinear Diffie--Hellman (BDH). Δοθέντων των στοιχείων

\[
(g,a g,b g,c g)
\]

για τυχαίες τιμές

\[
a,b,c \in \mathbb{Z}_q,
\]

θεωρείται υπολογιστικά ανέφικτος ο υπολογισμός της ποσότητας

\[
e(g,g)^{abc}.
\]

Η παραδοχή αυτή αποτελεί μία από τις βασικότερες υποθέσεις ασφάλειας των pairing-based κρυπτογραφικών συστημάτων και χρησιμοποιείται ευρέως στη βιβλιογραφία για την απόδειξη της ασφάλειας πρωτοκόλλων ομαδικής συμφωνίας κλειδιού.

Με την ολοκλήρωση της φάσης αρχικοποίησης, όλοι οι συμμετέχοντες διαθέτουν ένα κοινό σύνολο κρυπτογραφικών παραμέτρων και είναι πλέον δυνατή η εκτέλεση των επόμενων σταδίων του πρωτοκόλλου, τα οποία αφορούν τη δημιουργία των κλειδιών χρηστών και την παραγωγή του κοινού ομαδικού κλειδιού.

\section{Δημιουργία και Διαχείριση Κλειδιών}

Μετά την ολοκλήρωση της φάσης αρχικοποίησης, κάθε χρήστης που επιθυμεί να συμμετάσχει στο σύστημα πρέπει να αποκτήσει τα απαραίτητα κρυπτογραφικά διαπιστευτήρια. Η διαδικασία αυτή πραγματοποιείται μία φορά κατά την εγγραφή του χρήστη και έχει ως στόχο τη δημιουργία ενός μοναδικού ζεύγους δημόσιου και ιδιωτικού κλειδιού.

Έστω ότι ένας χρήστης $u_i$ επιθυμεί να ενταχθεί στο δίκτυο. Αρχικά δημιουργεί μια μοναδική ταυτότητα:

\[
ID_i
\]

η οποία μπορεί να αντιστοιχεί σε όνομα χρήστη, διεύθυνση ηλεκτρονικού ταχυδρομείου, αναγνωριστικό συσκευής ή οποιοδήποτε άλλο μοναδικό στοιχείο ταυτοποίησης.

Η ταυτότητα αυτή χρησιμοποιείται για την αναγνώριση του χρήστη εντός του συστήματος και συνδέεται με τα κρυπτογραφικά του κλειδιά.

Στη συνέχεια ο χρήστης επιλέγει τυχαία ένα ιδιωτικό κλειδί:

\[
sk_i \in \mathbb{Z}_q^{*}.
\]

Το ιδιωτικό κλειδί παραμένει γνωστό αποκλειστικά στον ίδιο τον χρήστη και δεν μεταδίδεται ποτέ μέσω του δικτύου.

Με βάση το ιδιωτικό κλειδί, υπολογίζεται το αντίστοιχο δημόσιο κλειδί:

\[
pk_i = sk_i \cdot g.
\]

Η πράξη αυτή αντιστοιχεί σε scalar multiplication πάνω στην ελλειπτική καμπύλη και παράγει ένα σημείο της ομάδας $G_1$.

Το δημόσιο κλειδί μπορεί να δημοσιοποιηθεί χωρίς να αποκαλύπτεται το ιδιωτικό κλειδί, λόγω της δυσκολίας επίλυσης του προβλήματος του διακριτού λογαρίθμου σε ελλειπτικές καμπύλες.

Μετά τη δημιουργία του ζεύγους κλειδιών, ο χρήστης αποστέλλει προς το δίκτυο τις πληροφορίες:

\[
(ID_i, pk_i).
\]

Οι πληροφορίες αυτές αποθηκεύονται στο blockchain και καθίστανται διαθέσιμες σε όλους τους εξουσιοδοτημένους συμμετέχοντες.

Η αποθήκευση στο blockchain εξασφαλίζει ότι:

\begin{itemize}
\item τα δημόσια κλειδιά δεν μπορούν να αλλοιωθούν,
\item η ταυτότητα κάθε συμμετέχοντα είναι επαληθεύσιμη,
\item όλες οι μεταβολές καταγράφονται με χρονική σήμανση,
\item παρέχεται πλήρης ιχνηλασιμότητα των ενεργειών.
\end{itemize}

Στο περιβάλλον Hyperledger Fabric, οι ταυτότητες των χρηστών συνδέονται επιπλέον με ψηφιακά πιστοποιητικά που εκδίδονται από την αντίστοιχη Certificate Authority (CA).

Κάθε πιστοποιητικό περιλαμβάνει:

\begin{itemize}
\item το αναγνωριστικό του χρήστη,
\item το δημόσιο κλειδί του,
\item πληροφορίες οργανισμού,
\item χρονική περίοδο ισχύος,
\item ψηφιακή υπογραφή της CA.
\end{itemize}

Η χρήση πιστοποιητικών επιτρέπει στο Membership Service Provider (MSP) του Hyperledger Fabric να πραγματοποιεί διαδικασίες αυθεντικοποίησης και εξουσιοδότησης πριν από οποιαδήποτε αλληλεπίδραση με το δίκτυο.

Μετά την ολοκλήρωση της διαδικασίας εγγραφής όλων των συμμετεχόντων, πραγματοποιείται μια κοινά αποδεκτή ταξινόμηση των χρηστών. Η ταξινόμηση αυτή είναι απαραίτητη ώστε όλοι οι κόμβοι να ακολουθούν την ίδια σειρά κατά την εκτέλεση του πρωτοκόλλου.

Έστω ότι η τελική διάταξη των χρηστών είναι:

\[
U = \{u_1,u_2,\ldots,u_n\}.
\]

Η σειρά αυτή μπορεί να προκύπτει από:

\begin{itemize}
\item λεξικογραφική ταξινόμηση των ταυτοτήτων,
\item ταξινόμηση βάσει δικτυακής διεύθυνσης,
\item ταξινόμηση βάσει hash των δημόσιων κλειδιών.
\end{itemize}

Η ντετερμινιστική ταξινόμηση εξασφαλίζει ότι όλοι οι συμμετέχοντες καταλήγουν στην ίδια ακολουθία εκτέλεσης χωρίς να απαιτείται πρόσθετος συντονισμός.

Μετά την ολοκλήρωση της διαδικασίας δημιουργίας και δημοσίευσης των κλειδιών, κάθε χρήστης διαθέτει:

\[
(ID_i, sk_i, pk_i).
\]

Το ιδιωτικό κλειδί $sk_i$ χρησιμοποιείται για την παραγωγή υπογραφών και τη συμμετοχή στον υπολογισμό του ομαδικού κλειδιού, ενώ το δημόσιο κλειδί $pk_i$ χρησιμοποιείται για την επαλήθευση των μηνυμάτων και των κρυπτογραφικών αποδείξεων που ανταλλάσσονται κατά την εκτέλεση του πρωτοκόλλου.

Η ολοκλήρωση του σταδίου αυτού σηματοδοτεί την ετοιμότητα των συμμετεχόντων για την εκκίνηση της διαδικασίας συμφωνίας ομαδικού κλειδιού, η οποία παρουσιάζεται στην επόμενη ενότητα.

\section{Πρωτόκολλο Συμφωνίας Ομαδικού Κλειδιού}

Μετά την ολοκλήρωση της διαδικασίας εγγραφής και δημοσίευσης των δημόσιων κλειδιών, οι συμμετέχοντες είναι έτοιμοι να εκτελέσουν το πρωτόκολλο συμφωνίας ομαδικού κλειδιού. Σκοπός του πρωτοκόλλου είναι η παραγωγή ενός κοινού μυστικού κλειδιού το οποίο θα είναι γνωστό αποκλειστικά στα νόμιμα μέλη της ομάδας.

Η διαδικασία βασίζεται στη συνεισφορά όλων των συμμετεχόντων και ανήκει στην κατηγορία των contributory group key agreement protocols, καθώς κάθε χρήστης εισάγει τη δική του τυχαία πληροφορία στον τελικό υπολογισμό του κλειδιού.

Έστω ότι η ομάδα αποτελείται από τους χρήστες:

\[
U = \{u_1,u_2,\ldots,u_n\}.
\]

Η σειρά εκτέλεσης θεωρείται ήδη γνωστή από το προηγούμενο στάδιο και είναι κοινή για όλους τους συμμετέχοντες.

\subsection{Παραγωγή Τυχαίων Τιμών}

Για κάθε νέα εκτέλεση του πρωτοκόλλου, κάθε χρήστης $u_i$ επιλέγει ανεξάρτητα μία νέα τυχαία τιμή:

\[
m_i \in \mathbb{Z}_q^{*}.
\]

Η τιμή αυτή αποτελεί την προσωρινή μυστική συνεισφορά του χρήστη στη συγκεκριμένη συνεδρία.

Η επιλογή νέας τυχαίας τιμής σε κάθε εκτέλεση είναι απαραίτητη για την επίτευξη forward secrecy, καθώς αποτρέπει τη συσχέτιση διαφορετικών συνεδριών μεταξύ τους.

Οι τιμές $m_i$ παραμένουν ιδιωτικές και δεν αποκαλύπτονται ποτέ στο δίκτυο.

\subsection{Υπολογισμός Δημόσιων Συνεισφορών}

Αφού επιλεγεί η τυχαία τιμή $m_i$, ο χρήστης υπολογίζει:

\[
M_i = m_i g.
\]

Η τιμή $M_i$ αποτελεί τη δημόσια συνεισφορά του χρήστη στην τρέχουσα εκτέλεση.

Όλοι οι συμμετέχοντες δημοσιεύουν τις αντίστοιχες τιμές τους:

\[
M_1,M_2,\ldots,M_n.
\]

Οι τιμές αυτές αποστέλλονται μέσω του δικτύου και καταγράφονται στο blockchain ώστε να είναι διαθέσιμες για μελλοντική επαλήθευση.

Η γνώση του $M_i$ δεν επιτρέπει τον υπολογισμό του $m_i$, λόγω της δυσκολίας επίλυσης του προβλήματος διακριτού λογαρίθμου πάνω στην ελλειπτική καμπύλη.

\subsection{Δημιουργία Κρυπτογραφικής Δέσμευσης}

Για την προστασία της ακεραιότητας των μηνυμάτων, κάθε κόμβος δημιουργεί μια κρυπτογραφική δέσμευση.

Έστω ότι ο χρήστης $u_i$ έχει στη διάθεσή του το ιστορικό ανταλλαγής μηνυμάτων μέχρι τη χρονική στιγμή παραγωγής της δέσμευσης.

Το ιστορικό αυτό συμβολίζεται ως:

\[
transcript_i.
\]

Στη συνέχεια υπολογίζεται:

\[
h_i =
H_2
\left(
M_i
\parallel
pk_i
\parallel
transcript_i
\right).
\]

Η τιμή $h_i$ δεσμεύει κρυπτογραφικά όλα τα στοιχεία που συμμετέχουν στην εκτέλεση.

Οποιαδήποτε τροποποίηση των ανταλλασσόμενων δεδομένων θα οδηγήσει σε διαφορετική τιμή hash και κατά συνέπεια σε αποτυχία της διαδικασίας επαλήθευσης.

\subsection{Δημιουργία Ψηφιακής Υπογραφής}

Μετά τον υπολογισμό της τιμής κατακερματισμού, κάθε χρήστης δημιουργεί μια κρυπτογραφική υπογραφή που συνδέει το δημόσιο μήνυμα με την ταυτότητά του.

Η υπογραφή ορίζεται ως:

\[
Sig_i =
sk_i \cdot h_i
+
sk_i \cdot M_i.
\]

Η τιμή αυτή ενσωματώνει τόσο τη μυστική πληροφορία του χρήστη όσο και τη δημόσια συνεισφορά του.

Κατά συνέπεια, οποιαδήποτε προσπάθεια παραποίησης των δεδομένων καθίσταται ανιχνεύσιμη από τους υπόλοιπους συμμετέχοντες.

\subsection{Ανταλλαγή Μηνυμάτων}

Ο κάθε χρήστης μεταδίδει στο δίκτυο το ακόλουθο σύνολο πληροφοριών:

\[
\left(
ID_i,
pk_i,
M_i,
Sig_i
\right).
\]

Τα δεδομένα αυτά μπορούν να μεταδοθούν είτε απευθείας στους υπόλοιπους κόμβους είτε μέσω της υποδομής Hyperledger Fabric.

Η καταγραφή των δεδομένων στο blockchain παρέχει χρονική σήμανση, ακεραιότητα και δυνατότητα μεταγενέστερης επαλήθευσης.

Μετά την ολοκλήρωση της ανταλλαγής μηνυμάτων, κάθε συμμετέχων διαθέτει το πλήρες σύνολο:

\[
\{
(ID_i,pk_i,M_i,Sig_i)
\}_{i=1}^{n}.
\]

Το σύνολο αυτό αποτελεί την είσοδο για τη διαδικασία επαλήθευσης και τον τελικό υπολογισμό του ομαδικού κλειδιού.

Στο επόμενο στάδιο, κάθε κόμβος επαληθεύει την εγκυρότητα όλων των μηνυμάτων που έλαβε πριν συμμετάσχει στον υπολογισμό του κοινού μυστικού κλειδιού.

\section{Επαλήθευση Μηνυμάτων}

Πριν από τον υπολογισμό του τελικού ομαδικού κλειδιού, κάθε συμμετέχων οφείλει να επαληθεύσει την εγκυρότητα όλων των μηνυμάτων που έλαβε κατά τη διάρκεια της εκτέλεσης του πρωτοκόλλου. Η διαδικασία αυτή είναι απαραίτητη ώστε να αποκλειστούν κακόβουλοι ή εσφαλμένοι κόμβοι που επιχειρούν να εισάγουν μη έγκυρες τιμές στον υπολογισμό του κοινού κλειδιού.

Η επαλήθευση πραγματοποιείται ανεξάρτητα από κάθε χρήστη και βασίζεται στις ιδιότητες της διγραμμικής απεικόνισης. Για κάθε συμμετέχοντα $u_i$, οι υπόλοιποι κόμβοι διαθέτουν τα ακόλουθα δημόσια δεδομένα:

\[
(ID_i, pk_i, M_i, Sig_i).
\]

Επιπλέον, κάθε κόμβος μπορεί να ανακατασκευάσει το αντίστοιχο ιστορικό ανταλλαγής μηνυμάτων και να υπολογίσει εκ νέου την τιμή

\[
h_i =
H_2
\left(
M_i
\parallel
pk_i
\parallel
transcript_i
\right).
\]

Η επαλήθευση πραγματοποιείται μέσω της σχέσης

\[
e(Sig_i,g)
=
e(h_i,pk_i)\cdot e(M_i,g).
\]

Εφόσον η παραπάνω ισότητα επαληθεύεται, το μήνυμα θεωρείται έγκυρο και ο χρήστης $u_i$ αναγνωρίζεται ως νόμιμος συμμετέχων της τρέχουσας εκτέλεσης.

Αντίθετα, εάν η ισότητα δεν ισχύει, το μήνυμα απορρίπτεται και ο αντίστοιχος κόμβος εξαιρείται από τη διαδικασία παραγωγής του ομαδικού κλειδιού.

Η διαδικασία αυτή εκτελείται για όλους τους συμμετέχοντες:

\[
u_1,u_2,\ldots,u_n.
\]

Μόνο όταν όλες οι επαληθεύσεις ολοκληρωθούν επιτυχώς επιτρέπεται η μετάβαση στο επόμενο στάδιο του πρωτοκόλλου.

Η χρήση της διγραμμικής απεικόνισης παρέχει έναν αποδοτικό μηχανισμό επαλήθευσης, καθώς επιτρέπει τη σύνδεση των δημόσιων παραμέτρων με τις αντίστοιχες υπογραφές χωρίς αποκάλυψη των ιδιωτικών κλειδιών των χρηστών.

Επιπλέον, η συμπερίληψη του ιστορικού ανταλλαγής μηνυμάτων στον υπολογισμό της τιμής κατακερματισμού αποτρέπει επιθέσεις επανάληψης (replay attacks). Κάθε εκτέλεση του πρωτοκόλλου οδηγεί σε διαφορετική τιμή $h_i$, ακόμη και αν ο ίδιος χρήστης συμμετέχει πολλές φορές.

Η διαδικασία επαλήθευσης παρέχει τις ακόλουθες ιδιότητες ασφάλειας:

\begin{itemize}
\item αυθεντικότητα συμμετέχοντος,
\item ακεραιότητα ανταλλασσόμενων δεδομένων,
\item ανίχνευση παραποιημένων μηνυμάτων,
\item προστασία από replay attacks,
\item αποτροπή μη εξουσιοδοτημένης συμμετοχής.
\end{itemize}

Μετά την επιτυχή ολοκλήρωση όλων των ελέγχων, κάθε κόμβος διαθέτει ένα κοινά αποδεκτό και επαληθευμένο σύνολο δημόσιων συνεισφορών. Οι τιμές αυτές χρησιμοποιούνται στο επόμενο στάδιο για τον υπολογισμό του τελικού ομαδικού κλειδιού.

\section{Παραγωγή Ομαδικού Κλειδιού}

Μετά την επιτυχή ολοκλήρωση της διαδικασίας επαλήθευσης, όλοι οι συμμετέχοντες διαθέτουν ένα κοινό και αξιόπιστο σύνολο δημόσιων συνεισφορών:

\[
\{M_1,M_2,\ldots,M_n\}.
\]

Οι τιμές αυτές αποτελούν τη βάση για τον υπολογισμό του τελικού ομαδικού κλειδιού.

Σε αντίθεση με τα κλασικά πρωτόκολλα Diffie--Hellman, όπου το τελικό μυστικό προκύπτει από διαδοχικές εκθετικοποιήσεις, στο προτεινόμενο σχήμα αξιοποιούνται οι ιδιότητες της διγραμμικής απεικόνισης ώστε να παραχθεί ένα κοινό μυστικό το οποίο εξαρτάται από τη συνεισφορά όλων των συμμετεχόντων.

\subsection{Παραγωγή των Τιμών \(f_i\)}

Μετά την ολοκλήρωση της αλυσίδας ανταλλαγής μηνυμάτων, ο τελευταίος κόμβος της εκτέλεσης, συμβολιζόμενος ως \(u_n\), επιλέγει μία νέα τυχαία τιμή:

\[
t_n \in \mathbb{Z}_q^{*}.
\]

Η τιμή αυτή αποτελεί τον τελικό παράγοντα μυστικότητας της συνεδρίας και χρησιμοποιείται για τη δημιουργία του κοινού κλειδιού.

Στη συνέχεια ο κόμβος υπολογίζει:

\[
f_1=t_nM_1,
\]

\[
f_2=t_nM_2,
\]

\[
\vdots
\]

\[
f_n=t_nM_n.
\]

Γενικά:

\[
f_i=t_nM_i,
\qquad
1 \leq i \leq n.
\]

Επειδή κάθε δημόσια συνεισφορά έχει τη μορφή

\[
M_i=m_i g,
\]

προκύπτει:

\[
f_i=t_nm_i g.
\]

Οι τιμές αυτές ενσωματώνουν τόσο τη μυστική συμβολή του χρήστη \(u_i\) όσο και την τυχαία τιμή \(t_n\) που εισάγει ο τελευταίος κόμβος.

\subsection{Υπολογισμός της Παραμέτρου \(\beta\)}

Αφού παραχθούν όλες οι τιμές \(f_i\), ο τελευταίος κόμβος υπολογίζει το άθροισμά τους:

\[
\beta=
\sum_{i=1}^{n} f_i.
\]

Αναπτύσσοντας τον παραπάνω τύπο προκύπτει:

\[
\beta
=
t_n
\sum_{i=1}^{n} M_i.
\]

Η παράμετρος \(\beta\) αποτελεί μια συλλογική αναπαράσταση της συνεισφοράς όλων των συμμετεχόντων και χρησιμοποιείται στη συνέχεια για την παραγωγή του τελικού κλειδιού.

Ο κόμβος \(u_n\) δημοσιεύει στο δίκτυο το σύνολο:

\[
(f_1,f_2,\ldots,f_n),
\]

ώστε όλοι οι υπόλοιποι συμμετέχοντες να μπορούν να ολοκληρώσουν τοπικά τον υπολογισμό του ομαδικού κλειδιού.

\subsection{Τοπικός Υπολογισμός της Παραμέτρου \(\alpha_i\)}

Αφού κάθε κόμβος λάβει τις τιμές \(f_i\), χρησιμοποιεί τη δική του μυστική τιμή \(m_i\) για να υπολογίσει:

\[
\alpha_i
=
m_i^{-1}f_i.
\]

Αντικαθιστώντας το \(f_i=t_nm_i g\), προκύπτει:

\[
\alpha_i
=
m_i^{-1}(t_nm_ig).
\]

Λόγω της ύπαρξης του αντιστρόφου του \(m_i\) στο \(\mathbb{Z}_q^{*}\), έχουμε:

\[
\alpha_i=t_ng.
\]

Επομένως όλοι οι συμμετέχοντες καταλήγουν στην ίδια ακριβώς τιμή \(\alpha_i\), ανεξάρτητα από το ποια ήταν η αρχική τους τυχαία συνεισφορά.

\subsection{Υπολογισμός του Τελικού Ομαδικού Κλειδιού}

Μετά τον υπολογισμό των \(\alpha_i\) και \(\beta\), κάθε συμμετέχων υπολογίζει το τελικό ομαδικό κλειδί μέσω της διγραμμικής απεικόνισης:

\[
GK_i=e(\alpha_i,\beta).
\]

Αντικαθιστώντας τις προηγούμενες σχέσεις:

\[
GK_i
=
e
\left(
t_ng,
t_n
\sum_{j=1}^{n}M_j
\right).
\]

Εφαρμόζοντας τη διγραμμικότητα της απεικόνισης:

\[
GK_i
=
e
\left(
g,
\sum_{j=1}^{n}M_j
\right)^{t_n^2}.
\]

Παρατηρούμε ότι το τελικό κλειδί εξαρτάται τόσο από την τυχαία τιμή \(t_n\) όσο και από το σύνολο των δημόσιων συνεισφορών όλων των συμμετεχόντων.

Επομένως:

\[
GK_1=GK_2=\cdots=GK_n.
\]

Όλοι οι χρήστες παράγουν το ίδιο κοινό μυστικό χωρίς να απαιτείται περαιτέρω ανταλλαγή πληροφοριών.

\subsection{Αυτοπιστοποίηση του Κλειδιού}

Ένα ιδιαίτερο χαρακτηριστικό του πρωτοκόλλου είναι ότι το παραγόμενο ομαδικό κλειδί μπορεί να επαληθευθεί χωρίς επιπλέον επικοινωνία μεταξύ των συμμετεχόντων.

Κάθε χρήστης μπορεί να ελέγξει την ορθότητα του υπολογισμού του μέσω της σχέσης:

\[
e
\left(
\alpha_i,
\sum_{j=1}^{n}M_j
\right)
=
e(\beta,g).
\]

Εάν η παραπάνω ισότητα ισχύει, τότε ο χρήστης γνωρίζει ότι το παραγόμενο κλειδί είναι συνεπές με τις δημόσιες συνεισφορές όλων των μελών της ομάδας.

Η ιδιότητα αυτή είναι γνωστή ως \textit{key self-certification} και μειώνει σημαντικά το επικοινωνιακό κόστος, καθώς δεν απαιτείται ανταλλαγή πρόσθετων μηνυμάτων επιβεβαίωσης.

\section{Ενσωμάτωση Blockchain}

Σε αντίθεση με τα κλασικά πρωτόκολλα Group Key Agreement, όπου η ανταλλαγή των μηνυμάτων πραγματοποιείται αποκλειστικά μέσω καναλιών επικοινωνίας μεταξύ των συμμετεχόντων, το προτεινόμενο πρωτόκολλο αξιοποιεί μια υποδομή blockchain για την καταγραφή και επαλήθευση κρίσιμων δεδομένων της εκτέλεσης.

Η υποδομή blockchain βασίζεται στο Hyperledger Fabric, ένα permissioned blockchain framework το οποίο επιτρέπει τον έλεγχο ταυτότητας των συμμετεχόντων, τη διαχείριση πολιτικών πρόσβασης και την αποθήκευση δεδομένων σε αμετάβλητο κατανεμημένο καθολικό.

Ο κύριος στόχος της ενσωμάτωσης του blockchain είναι η παροχή μηχανισμών ακεραιότητας, ιχνηλασιμότητας και μη αποποίησης ευθύνης κατά τη διάρκεια της διαδικασίας συμφωνίας του ομαδικού κλειδιού.

\subsection{Καταγραφή Δημοσίων Παραμέτρων}

Κατά την έναρξη του πρωτοκόλλου, οι συμμετέχοντες δημοσιεύουν τις δημόσιες πληροφορίες τους στο blockchain.

Για κάθε χρήστη $u_i$ αποθηκεύονται:

\[
(ID_i,pk_i).
\]

Οι πληροφορίες αυτές καταγράφονται ως συναλλαγές στο καθολικό και είναι διαθέσιμες σε όλους τους εξουσιοδοτημένους συμμετέχοντες.

Με τον τρόπο αυτό αποτρέπεται η αντικατάσταση δημόσιων κλειδιών από κακόβουλους χρήστες και διασφαλίζεται η ύπαρξη ενός μοναδικού σημείου αναφοράς για την επαλήθευση των ταυτοτήτων.

\subsection{Καταγραφή Δημοσίων Συνεισφορών}

Κατά την εκτέλεση του πρωτοκόλλου, κάθε χρήστης δημιουργεί τη δημόσια συνεισφορά:

\[
M_i=m_i g.
\]

Η τιμή αυτή καταγράφεται στο blockchain μαζί με τα αντίστοιχα μεταδεδομένα της εκτέλεσης.

Για κάθε συμμετέχοντα δημιουργείται μία εγγραφή της μορφής:

\[
(ID_i,M_i,timestamp).
\]

Η χρονική σήμανση επιτρέπει την ανακατασκευή της ακολουθίας των γεγονότων ακόμη και μετά την ολοκλήρωση της συνεδρίας.

\subsection{Καταγραφή Υπογραφών}

Εκτός από τις δημόσιες συνεισφορές, στο blockchain αποθηκεύονται και οι παραγόμενες υπογραφές:

\[
Sig_i.
\]

Οι υπογραφές χρησιμοποιούνται ως αποδεικτικά στοιχεία ότι ο αντίστοιχος χρήστης συμμετείχε στην εκτέλεση του πρωτοκόλλου.

Η ύπαρξη των υπογραφών στο καθολικό επιτρέπει τη μεταγενέστερη επαλήθευση της διαδικασίας χωρίς να απαιτείται πρόσβαση στους αρχικούς συμμετέχοντες.

\subsection{Χρήση Chaincode}

Η αλληλεπίδραση των συμμετεχόντων με το blockchain πραγματοποιείται μέσω chaincode υλοποιημένου στο Hyperledger Fabric.

Το chaincode είναι υπεύθυνο για:

\begin{itemize}
\item την καταχώριση δημόσιων κλειδιών,
\item την αποθήκευση των τιμών $M_i$,
\item την αποθήκευση των υπογραφών $Sig_i$,
\item την καταγραφή των χρονικών σφραγίδων,
\item την ανάκτηση δεδομένων προηγούμενων εκτελέσεων.
\end{itemize}

Κάθε συναλλαγή που υποβάλλεται στο chaincode επικυρώνεται από τους peers του δικτύου πριν καταγραφεί οριστικά στο ledger.

\subsection{Ρόλος των Peers}

Οι peer nodes του Hyperledger Fabric λειτουργούν ως κατανεμημένοι επαληθευτές των δεδομένων του πρωτοκόλλου.

Κάθε peer:

\begin{itemize}
\item διατηρεί αντίγραφο του ledger,
\item εκτελεί το chaincode,
\item επικυρώνει συναλλαγές,
\item συμμετέχει στη διαδικασία endorsement.
\end{itemize}

Η ύπαρξη πολλαπλών peers εξαλείφει την εξάρτηση από έναν μοναδικό εξυπηρετητή και αυξάνει την ανθεκτικότητα του συστήματος.

\subsection{Ρόλος των Orderers}

Οι orderer nodes είναι υπεύθυνοι για τη δημιουργία της τελικής ακολουθίας των συναλλαγών.

Οι συναλλαγές που αφορούν:

\[
pk_i,\;
M_i,\;
Sig_i
\]

συγκεντρώνονται από το ordering service και οργανώνονται σε blocks.

Στη συνέχεια τα blocks διανέμονται στους peers για τελική επικύρωση και αποθήκευση.

Η διαδικασία αυτή εξασφαλίζει ότι όλοι οι συμμετέχοντες διαθέτουν ακριβώς την ίδια εικόνα της εκτέλεσης του πρωτοκόλλου.

\subsection{Ιχνηλασιμότητα και Μη Αποποίηση Ευθύνης}

Η καταγραφή όλων των κρίσιμων γεγονότων στο blockchain παρέχει πλήρη δυνατότητα ελέγχου της εκτέλεσης.

Ένας εξουσιοδοτημένος ελεγκτής μπορεί να ανακτήσει:

\[
(pk_i,M_i,Sig_i,timestamp)
\]

για οποιονδήποτε συμμετέχοντα και να επαληθεύσει ανεξάρτητα την ορθότητα των ενεργειών του.

Επιπλέον, επειδή οι εγγραφές είναι αμετάβλητες μετά την επικύρωσή τους, κανένας συμμετέχων δεν μπορεί να αρνηθεί μεταγενέστερα ότι έλαβε μέρος στη διαδικασία.

Η ιδιότητα αυτή είναι ιδιαίτερα σημαντική σε επιχειρησιακά και βιομηχανικά περιβάλλοντα όπου απαιτείται λογοδοσία και πλήρες audit trail.

\subsection{Πλεονεκτήματα της Ενσωμάτωσης Blockchain}

Η χρήση του Hyperledger Fabric προσθέτει ένα επιπλέον επίπεδο ασφάλειας στο προτεινόμενο πρωτόκολλο.

Συγκεκριμένα παρέχει:

\begin{itemize}
\item αμετάβλητη αποθήκευση δεδομένων,
\item αποκεντρωμένη επαλήθευση,
\item προστασία από αλλοίωση μηνυμάτων,
\item πλήρη ιχνηλασιμότητα,
\item μη αποποίηση ευθύνης,
\item δυνατότητα μεταγενέστερου ελέγχου της εκτέλεσης.
\end{itemize}

Ως αποτέλεσμα, το blockchain δεν λειτουργεί απλώς ως μηχανισμός αποθήκευσης, αλλά ως ενεργό συστατικό της αρχιτεκτονικής ασφάλειας του προτεινόμενου πρωτοκόλλου.

\section{Ανάλυση Ορθότητας}

Στην παρούσα ενότητα αποδεικνύεται ότι όλοι οι νόμιμοι συμμετέχοντες του πρωτοκόλλου καταλήγουν στο ίδιο ομαδικό κλειδί μετά την ολοκλήρωση της διαδικασίας ανταλλαγής μηνυμάτων και των αντίστοιχων υπολογισμών.

Η ορθότητα του πρωτοκόλλου βασίζεται στις ιδιότητες της διγραμμικής απεικόνισης και στη συνεπή χρήση των δημόσιων και ιδιωτικών παραμέτρων από όλους τους συμμετέχοντες.

Έστω ότι κάθε χρήστης $u_i$ επιλέγει μία τυχαία τιμή:

\[
m_i \in \mathbb{Z}_q^{*}
\]

και υπολογίζει τη δημόσια συνεισφορά:

\[
M_i=m_i g.
\]

Μετά την ολοκλήρωση της διαδικασίας ανταλλαγής μηνυμάτων, ο τελευταίος κόμβος επιλέγει μία επιπλέον τυχαία τιμή:

\[
t_n \in \mathbb{Z}_q^{*}.
\]

Στη συνέχεια παράγει για κάθε συμμετέχοντα την τιμή:

\[
f_i=t_nM_i.
\]

Αντικαθιστώντας τον ορισμό του $M_i$ προκύπτει:

\[
f_i=t_n(m_ig).
\]

Λόγω της προσεταιριστικής ιδιότητας του scalar multiplication έχουμε:

\[
f_i=t_nm_ig.
\]

Κάθε χρήστης παραλαμβάνει την αντίστοιχη τιμή $f_i$ και υπολογίζει:

\[
\alpha_i=m_i^{-1}f_i.
\]

Αντικαθιστώντας το $f_i$ προκύπτει:

\[
\alpha_i
=
m_i^{-1}(t_nm_ig).
\]

Επειδή το $m_i$ ανήκει στο $\mathbb{Z}_q^{*}$ διαθέτει μοναδικό αντίστροφο modulo $q$.

Επομένως:

\[
m_i^{-1}m_i=1.
\]

Άρα:

\[
\alpha_i=t_ng.
\]

Παρατηρούμε ότι το αποτέλεσμα αυτό είναι ανεξάρτητο από τον δείκτη $i$.

Συνεπώς:

\[
\alpha_1=\alpha_2=\cdots=\alpha_n=t_ng.
\]

Στη συνέχεια ο τελευταίος κόμβος υπολογίζει:

\[
\beta=\sum_{j=1}^{n}f_j.
\]

Αντικαθιστώντας τους ορισμούς των $f_j$:

\[
\beta
=
\sum_{j=1}^{n}t_nM_j.
\]

Εξάγοντας τον κοινό παράγοντα:

\[
\beta
=
t_n\sum_{j=1}^{n}M_j.
\]

Όλοι οι συμμετέχοντες διαθέτουν πλέον τις ίδιες τιμές $\beta$ και $\alpha_i$.

Το τελικό ομαδικό κλειδί ορίζεται ως:

\[
GK_i=e(\alpha_i,\beta).
\]

Αντικαθιστώντας τα προηγούμενα αποτελέσματα:

\[
GK_i
=
e
\left(
t_ng,
t_n\sum_{j=1}^{n}M_j
\right).
\]

Από τη διγραμμικότητα της απεικόνισης προκύπτει:

\[
GK_i
=
e
\left(
g,
\sum_{j=1}^{n}M_j
\right)^{t_n^2}.
\]

Η παραπάνω έκφραση δεν περιέχει καμία μεταβλητή που να εξαρτάται από συγκεκριμένο συμμετέχοντα.

Επομένως για κάθε ζεύγος χρηστών $u_i$ και $u_j$ ισχύει:

\[
GK_i=GK_j.
\]

Άρα:

\[
GK_1
=
GK_2
=
\cdots
=
GK_n.
\]

Συνεπώς όλοι οι νόμιμοι συμμετέχοντες παράγουν ακριβώς το ίδιο ομαδικό κλειδί.

Επιπλέον, επειδή το τελικό κλειδί εξαρτάται από:

\[
M_1,M_2,\ldots,M_n
\]

και από την τυχαία τιμή:

\[
t_n,
\]

η συνεισφορά κάθε συμμετέχοντα επηρεάζει άμεσα το τελικό αποτέλεσμα.

Η ιδιότητα αυτή εξασφαλίζει ότι το πρωτόκολλο ανήκει στην κατηγορία των contributory group key agreement protocols, καθώς κανένας συμμετέχων δεν μπορεί να καθορίσει μονομερώς το τελικό κλειδί.

Επομένως, υπό την προϋπόθεση ότι όλοι οι κόμβοι ακολουθούν πιστά τα βήματα του πρωτοκόλλου και ότι οι επαληθεύσεις ολοκληρώνονται επιτυχώς, το προτεινόμενο σχήμα οδηγεί πάντοτε στην παραγωγή ενός μοναδικού και κοινού ομαδικού κλειδιού για όλα τα μέλη της ομάδας.

\section{Ανάλυση Ασφάλειας}

Στην ενότητα αυτή αναλύονται οι ιδιότητες ασφάλειας του προτεινόμενου πρωτοκόλλου και αξιολογείται η ανθεκτικότητά του έναντι γνωστών επιθέσεων. Η ασφάλεια του συστήματος βασίζεται τόσο στις μαθηματικές ιδιότητες των διγραμμικών ζευγοποιήσεων όσο και στους μηχανισμούς ακεραιότητας και καταγραφής που προσφέρει το Hyperledger Fabric.

Υποθέτουμε ότι ο αντίπαλος έχει πλήρη πρόσβαση στο δημόσιο δίκτυο επικοινωνίας, μπορεί να παρακολουθεί, να καταγράφει και να επαναμεταδίδει μηνύματα, αλλά δεν μπορεί να επιλύσει αποδοτικά το πρόβλημα Bilinear Diffie--Hellman (BDH).

\subsection{Αυθεντικοποίηση Συμμετεχόντων}

Η αυθεντικοποίηση των χρηστών επιτυγχάνεται μέσω του συνδυασμού δημοσίων κλειδιών, ψηφιακών υπογραφών και πιστοποιητικών του Hyperledger Fabric.

Για κάθε χρήστη $u_i$ ισχύει:

\[
pk_i = sk_i g.
\]

Οι υπογραφές που παράγονται κατά την εκτέλεση του πρωτοκόλλου συνδέονται άμεσα με το αντίστοιχο ιδιωτικό κλειδί. Κατά συνέπεια, ένας επιτιθέμενος που δεν γνωρίζει το $sk_i$ αδυνατεί να δημιουργήσει έγκυρη υπογραφή για λογαριασμό του χρήστη.

Επιπλέον, η ύπαρξη πιστοποιητικών που εκδίδονται από την Certificate Authority του Fabric εξασφαλίζει ότι κάθε δημόσιο κλειδί αντιστοιχεί σε πραγματικό και εξουσιοδοτημένο συμμετέχοντα.

\subsection{Ακεραιότητα Δεδομένων}

Η ακεραιότητα των ανταλλασσόμενων δεδομένων εξασφαλίζεται μέσω της συνάρτησης κατακερματισμού:

\[
h_i =
H_2
\left(
M_i
\parallel
pk_i
\parallel
transcript_i
\right).
\]

Οποιαδήποτε τροποποίηση των δεδομένων οδηγεί σε διαφορετική τιμή hash, με αποτέλεσμα την αποτυχία της διαδικασίας επαλήθευσης.

Επομένως, ένας επιτιθέμενος δεν μπορεί να μεταβάλει τα ανταλλασσόμενα μηνύματα χωρίς να γίνει αντιληπτός από τους υπόλοιπους συμμετέχοντες.

\subsection{Forward Secrecy}

Η ιδιότητα forward secrecy απαιτεί η αποκάλυψη ενός τρέχοντος κλειδιού να μην επιτρέπει την ανάκτηση παλαιότερων κλειδιών συνεδρίας.

Στο προτεινόμενο πρωτόκολλο κάθε εκτέλεση χρησιμοποιεί νέες τυχαίες τιμές:

\[
m_i \in \mathbb{Z}_q^{*}
\]

και

\[
t_n \in \mathbb{Z}_q^{*}.
\]

Επειδή οι τιμές αυτές δημιουργούνται εκ νέου σε κάθε συνεδρία, η αποκάλυψη ενός μεταγενέστερου ομαδικού κλειδιού δεν παρέχει πληροφορία για προηγούμενα κλειδιά.

Κατά συνέπεια, το πρωτόκολλο παρέχει forward secrecy.

\subsection{Backward Secrecy}

Η backward secrecy προστατεύει τις προηγούμενες συνεδρίες από νέους συμμετέχοντες.

Όταν ένας νέος χρήστης εισέρχεται στην ομάδα, εκτελείται νέα διαδικασία δημιουργίας ομαδικού κλειδιού με νέες τυχαίες τιμές.

Ο νέος χρήστης δεν διαθέτει πρόσβαση στις τυχαίες συνεισφορές που χρησιμοποιήθηκαν σε παλαιότερες συνεδρίες και συνεπώς δεν μπορεί να υπολογίσει τα αντίστοιχα ομαδικά κλειδιά.

\subsection{Key Independence}

Η ιδιότητα key independence απαιτεί κάθε ομαδικό κλειδί να είναι ανεξάρτητο από προηγούμενα ή μελλοντικά κλειδιά.

Δεδομένου ότι κάθε συνεδρία χρησιμοποιεί διαφορετικές τιμές:

\[
m_1,m_2,\ldots,m_n
\]

και διαφορετική τιμή:

\[
t_n,
\]

κάθε παραγόμενο κλειδί αποτελεί ανεξάρτητο αποτέλεσμα της εκτέλεσης.

Η γνώση ενός κλειδιού δεν επιτρέπει τον υπολογισμό οποιουδήποτε άλλου κλειδιού συνεδρίας.

\subsection{Ανθεκτικότητα σε Replay Attacks}

Σε μια επίθεση επανάληψης, ένας αντίπαλος επιχειρεί να επαναμεταδώσει παλαιά έγκυρα μηνύματα.

Στο προτεινόμενο πρωτόκολλο, η τιμή:

\[
h_i =
H_2
\left(
M_i
\parallel
pk_i
\parallel
transcript_i
\right)
\]

εξαρτάται από το ιστορικό της τρέχουσας εκτέλεσης.

Κατά συνέπεια, η επαναχρησιμοποίηση μηνυμάτων προηγούμενης συνεδρίας οδηγεί σε διαφορετική τιμή κατακερματισμού και αποτυχημένη επαλήθευση.

\subsection{Ανθεκτικότητα σε Man-in-the-Middle Επιθέσεις}

Ένας αντίπαλος που παρεμβάλλεται μεταξύ δύο χρηστών μπορεί να επιχειρήσει την αντικατάσταση δημοσίων συνεισφορών ή υπογραφών.

Ωστόσο, κάθε δημόσια συνεισφορά συνδέεται με:

\[
pk_i
\]

και με την αντίστοιχη υπογραφή:

\[
Sig_i.
\]

Η διαδικασία επαλήθευσης μέσω της διγραμμικής απεικόνισης απορρίπτει οποιαδήποτε αλλοιωμένη πληροφορία.

Επιπλέον, τα δημόσια κλειδιά είναι καταχωρημένα στο blockchain και δεν μπορούν να αντικατασταθούν χωρίς να εντοπιστεί η τροποποίηση.

\subsection{Ανθεκτικότητα σε Επιθέσεις Συνωμοσίας}

Ακόμη και αν ένα υποσύνολο χρηστών συνεργαστεί κακόβουλα, η παραγωγή του τελικού κλειδιού απαιτεί τη συνεισφορά όλων των συμμετεχόντων.

Το τελικό κλειδί εξαρτάται από:

\[
M_1,M_2,\ldots,M_n.
\]

Η απουσία οποιασδήποτε συνεισφοράς οδηγεί σε διαφορετικό αποτέλεσμα και συνεπώς εμποδίζει τον υπολογισμό του πραγματικού ομαδικού κλειδιού.

\subsection{Ακεραιότητα του Blockchain}

Η χρήση του Hyperledger Fabric παρέχει πρόσθετη προστασία έναντι αλλοίωσης δεδομένων.

Οι πληροφορίες που αποθηκεύονται στο ledger επικυρώνονται μέσω των endorsement policies και καταγράφονται σε αμετάβλητη μορφή.

Οποιαδήποτε προσπάθεια μεταβολής παλαιότερων εγγραφών θα γινόταν άμεσα αντιληπτή από τους υπόλοιπους peers του δικτύου.

\subsection{Σχέση με την Υπόθεση Bilinear Diffie--Hellman}

Η υπολογιστική ασφάλεια του πρωτοκόλλου βασίζεται στη δυσκολία επίλυσης του προβλήματος Bilinear Diffie--Hellman.

Δοθέντων των στοιχείων:

\[
(g,ag,bg,cg),
\]

θεωρείται υπολογιστικά ανέφικτος ο υπολογισμός της τιμής:

\[
e(g,g)^{abc}.
\]

Το τελικό ομαδικό κλειδί εξαρτάται από αντίστοιχους εκθετικούς συνδυασμούς που προκύπτουν από τις τυχαίες συνεισφορές των χρηστών.

Κατά συνέπεια, ένας αντίπαλος που δεν μπορεί να επιλύσει το πρόβλημα BDH δεν μπορεί να υπολογίσει το ομαδικό κλειδί ακόμη και αν διαθέτει πλήρη γνώση όλων των δημόσιων παραμέτρων και των μηνυμάτων που ανταλλάχθηκαν κατά τη διάρκεια του πρωτοκόλλου.

Συνολικά, το προτεινόμενο πρωτόκολλο ικανοποιεί τις βασικές απαιτήσεις ασφάλειας των σύγχρονων συστημάτων Group Key Agreement και συνδυάζει τις ιδιότητες των bilinear pairings με τους μηχανισμούς ακεραιότητας και ιχνηλασιμότητας που προσφέρει το Hyperledger Fabric.

\section{Spring Boot}

Το Spring Boot αποτελεί ένα από τα δημοφιλέστερα πλαίσια ανάπτυξης
(Java Frameworks) για τη δημιουργία εφαρμογών επιχειρησιακού επιπέδου.
Αναπτύχθηκε από την ομάδα του Spring Framework με στόχο την
απλοποίηση της διαδικασίας ανάπτυξης εφαρμογών μέσω της φιλοσοφίας
``Convention over Configuration''.

Η βασική ιδέα του Spring Boot είναι η παροχή προκαθορισμένων
ρυθμίσεων (auto-configuration), οι οποίες επιτρέπουν στον
προγραμματιστή να επικεντρωθεί στην επιχειρησιακή λογική της
εφαρμογής χωρίς να απαιτείται εκτεταμένη παραμετροποίηση.

Ένα από τα σημαντικότερα χαρακτηριστικά του είναι η ενσωμάτωση
ενσωματωμένων web servers, όπως οι Tomcat, Jetty και Undertow,
επιτρέποντας την εκτέλεση της εφαρμογής ως αυτόνομο εκτελέσιμο
αρχείο χωρίς την ανάγκη εξωτερικού application server.

Στην παρούσα εργασία το Spring Boot χρησιμοποιήθηκε για την
υλοποίηση τόσο του κεντρικού κόμβου (Master Node) όσο και των
συμμετεχόντων κόμβων του πρωτοκόλλου. Μέσω του framework
υλοποιήθηκαν τα REST APIs, οι JMS listeners, τα services και
οι μηχανισμοί επικοινωνίας με το blockchain δίκτυο.

\section{RESTful Web Services}

Η αρχιτεκτονική REST (Representational State Transfer) αποτελεί
ένα από τα επικρατέστερα πρότυπα σχεδίασης διαδικτυακών υπηρεσιών.

Στο μοντέλο αυτό οι λειτουργίες της εφαρμογής εκτίθενται μέσω
HTTP endpoints και προσπελαύνονται με χρήση μεθόδων όπως GET,
POST, PUT και DELETE.

Τα δεδομένα μεταφέρονται συνήθως σε μορφή JSON, γεγονός που
διευκολύνει τη διαλειτουργικότητα μεταξύ ετερογενών συστημάτων.

Στην παρούσα εργασία χρησιμοποιήθηκαν REST APIs για την
επικοινωνία των κόμβων με το blockchain layer. Μέσω των APIs
παρέχεται πρόσβαση στις λειτουργίες δημιουργίας, ανάγνωσης και
ανάκτησης blocks από το Hyperledger Fabric δίκτυο.

\section{Apache ActiveMQ Artemis}

Το Apache ActiveMQ Artemis αποτελεί έναν σύγχρονο message broker
υψηλών επιδόσεων, ο οποίος αναπτύσσεται στο πλαίσιο του Apache
Software Foundation.

Ο Artemis παρέχει αξιόπιστη ασύγχρονη επικοινωνία μεταξύ
κατανεμημένων εφαρμογών και υποστηρίζει πληθώρα πρωτοκόλλων,
όπως AMQP, MQTT, STOMP και JMS.

Η λειτουργία του βασίζεται στην έννοια των μηνυμάτων
(messages), τα οποία ανταλλάσσονται μέσω queues ή topics.

Στην παρούσα υλοποίηση ο Artemis χρησιμοποιείται ως μηχανισμός
επικοινωνίας μεταξύ των κόμβων του πρωτοκόλλου. Κάθε συμμετέχων
λαμβάνει και αποστέλλει μηνύματα μέσω ενός κοινού topic,
επιτρέποντας τη διάδοση πληροφοριών χωρίς άμεσες συνδέσεις
μεταξύ των κόμβων.

Η χρήση message broker αυξάνει την επεκτασιμότητα και την
αξιοπιστία του συστήματος, καθώς αποσυνδέει λογικά τους
αποστολείς από τους παραλήπτες.

\section{Java Message Service (JMS)}

Το Java Message Service (JMS) αποτελεί το πρότυπο ανταλλαγής
μηνυμάτων της πλατφόρμας Java.

Μέσω του JMS οι εφαρμογές μπορούν να επικοινωνούν με
ασύγχρονο τρόπο, χωρίς να απαιτείται ταυτόχρονη παρουσία
αποστολέα και παραλήπτη.

Το πρότυπο υποστηρίζει δύο βασικά μοντέλα επικοινωνίας:

\begin{itemize}
\item Point-to-Point (Queues)
\item Publish-Subscribe (Topics)
\end{itemize}

Στο μοντέλο Publish-Subscribe ένας παραγωγός μηνυμάτων
δημοσιεύει πληροφορίες σε ένα topic και πολλαπλοί
καταναλωτές μπορούν να λαμβάνουν τα ίδια μηνύματα.

Η συγκεκριμένη λειτουργία αξιοποιήθηκε στην παρούσα εργασία
για τη διάδοση των μηνυμάτων του πρωτοκόλλου BDGKA.
Τα μηνύματα τύπου START, PARTICIPANTS, GK-COMPUTATION και
GK-FINAL διακινούνται μέσω JMS topics και παραλαμβάνονται
από τους αντίστοιχους listeners κάθε κόμβου.

\section{Docker}

Το Docker αποτελεί πλατφόρμα εικονικοποίησης επιπέδου

Κάθε container περιλαμβάνει όλες τις απαραίτητες

διαχείριση και ανάπτυξη του συστήματος.

\section{JPBC Library}

Η βιβλιοθήκη Java Pairing Based Cryptography (JPBC)

κλειδιού του πρωτοκόλλου BDGKA.

\section{Hyperledger Fabric Network}

Το Hyperledger Fabric αποτελεί ένα open source blockchain framework με αρχιτεκτονική που βασίζεται σε peers, orderers και certificate authorities. Η πλατφόρμα λειτουργεί σε containerized περιβάλλον μέσω Docker και Docker Compose.

Οι οργανισμοί του δικτύου αντιπροσωπεύουν τους συμμετέχοντες φορείς. Στην παρούσα υλοποίηση χρησιμοποιείται test network με δύο οργανισμούς, όπου κάθε οργανισμός διαθέτει έναν Certificate Authority, έναν orderer και έναν peer.

Ο Certificate Authority είναι υπεύθυνος για την έκδοση πιστοποιητικών και τη διαχείριση ταυτοτήτων. Ο orderer συλλέγει συναλλαγές, τις ταξινομεί και δημιουργεί blocks. Ο peer διατηρεί το ledger και εκτελεί το smart contract.

Το σύστημα χρησιμοποιεί κανάλι με όνομα “myChannel”, το οποίο επιτρέπει ιδιωτική επικοινωνία μεταξύ των οργανισμών. Σε αυτό εγκαθίσταται το chaincode που υλοποιεί τη λογική του blockchain.
	\section{Organizations}
	Οι οργανισμοί είναι οι συμμετέχοντες στο δίκτυο, φερ'ειπιν οι εταιρίες
	Στην εφαρμογή χρησιμοποιούμε το τεστ δίκτυο που παρέχεται από το hyperledger fabric
	Το τεστ δίκτυο αποτελείται απο δύο οργανισμούς οι οποίοι έχουν 1 Certificate Authority , 1 Orderer , 1 peer
	\begin{itemize}
		\item Certificate Authority: εκδίδει ψηφιακά πιστοποιητικά , Ταυτοποιεί χρηστες και κόμβους , διαχειρίζεται τις ταυτότητες
		\item Orderer: Συλλέγουν τις συναλλαγές , τις ταξινομούν και δημιουργούν τα μπλοκ στο blockchain
		\item Peer: διατηρούνε αντίγραφο του ledger και εκτελούν τα smart contracts
	\end{itemize}
	\subsection*{Channel}
	Η εφαρμογή χρησιμοποιεί και δημιουργεί το κανάλι "myChannel"

	Στο κανάλι καταθέτουμε το $contract - chaincode$ που είναι η λογική της εφαρμογής όσο αφορά τις λειτουργίες του blockchain και εκτελείται στους peers

\section{Ροή Εκτέλεσης του Πρωτοκόλλου}

Η λειτουργία του συστήματος βασίζεται στη συνεργασία των συμμετεχόντων
κόμβων, του blockchain δικτύου Hyperledger Fabric και του συστήματος
ανταλλαγής μηνυμάτων. Σκοπός του πρωτοκόλλου είναι η παραγωγή ενός
κοινού ομαδικού κλειδιού (Group Key), το οποίο υπολογίζεται
συνεργατικά από όλους τους συμμετέχοντες χωρίς την ύπαρξη κεντρικού
διαχειριστή κλειδιών.

Η εκτέλεση του πρωτοκόλλου χωρίζεται σε διακριτές φάσεις οι οποίες
εκτελούνται διαδοχικά μέχρι την τελική παραγωγή και επαλήθευση του
κοινού μυστικού.

\subsection{Τύποι Μηνυμάτων}

Η επικοινωνία μεταξύ των κόμβων βασίζεται σε μηνύματα
JMS τα οποία μεταδίδονται μέσω του Artemis Message Broker.

Οι βασικοί τύποι μηνυμάτων που χρησιμοποιούνται είναι:

\begin{itemize}
\item START
\item PARTICIPANTS
\item INITIAL\_PK\_BROADCAST
\item GK-COMPUTATION
\item GK-FINAL
\end{itemize}

Κάθε τύπος αντιστοιχεί σε συγκεκριμένο στάδιο του
πρωτοκόλλου και ενεργοποιεί διαφορετική λειτουργικότητα
στον παραλήπτη.

\subsection{Φάση Εκκίνησης (START)}

Η πρώτη φάση του πρωτοκόλλου ξεκινά με την αποστολή ενός μηνύματος
τύπου \texttt{START} προς όλους τους ενεργούς κόμβους.

Κατά τη φάση αυτή κάθε κόμβος δημιουργεί το ζεύγος των
κρυπτογραφικών κλειδιών του. Συγκεκριμένα παράγεται ένα ιδιωτικό
κλειδί το οποίο αποτελεί τυχαίο στοιχείο του συνόλου
$\mathbb{Z}_r$ και το αντίστοιχο δημόσιο κλειδί το οποίο
προκύπτει από πράξη βαθμωτού πολλαπλασιασμού πάνω στον γεννήτορα
της ομάδας.

Μετά τη δημιουργία των κλειδιών κάθε κόμβος μεταδίδει το δημόσιο
κλειδί του στους υπόλοιπους συμμετέχοντες μέσω του συστήματος
ανταλλαγής μηνυμάτων.

\subsection{Φάση Καθορισμού Συμμετεχόντων}

Μετά την ανταλλαγή των δημοσίων κλειδιών οι κόμβοι αποκτούν
πληροφορίες σχετικά με όλους τους συμμετέχοντες του πρωτοκόλλου.

Οι συμμετέχοντες ταξινομούνται με βάση το αναγνωριστικό τους και
δημιουργείται μία λογική κυκλική τοπολογία επικοινωνίας.
Για κάθε κόμβο καθορίζεται ο προηγούμενος και ο επόμενος γείτονας.

Η πληροφορία αυτή χρησιμοποιείται στη συνέχεια για τη σειριακή
διάδοση των κρυπτογραφικών δεδομένων κατά τη διάρκεια του
υπολογισμού του ομαδικού κλειδιού.

\subsection{Φάση Ανταλλαγής Δημοσίων Κλειδιών}

Κατά τη φάση αυτή πραγματοποιείται η ανταλλαγή των δημοσίων
κλειδιών μεταξύ γειτονικών κόμβων.

Κάθε κόμβος αποθηκεύει τα δημόσια κλειδιά του προηγούμενου και
του επόμενου συμμετέχοντα ώστε να είναι δυνατή η επαλήθευση των
κρυπτογραφικών υπογραφών που θα ακολουθήσουν.

Η ύπαρξη των δημοσίων κλειδιών είναι απαραίτητη για την
επαλήθευση της προέλευσης κάθε block που καταγράφεται στο
blockchain.

\subsection{Φάση Δημιουργίας Blocks}

Ο πρώτος κόμβος της ακολουθίας δημιουργεί το αρχικό block του
πρωτοκόλλου.

Το block περιλαμβάνει:

\begin{itemize}
\item Το αναγνωριστικό του block.
\item Τη διεύθυνση του επόμενου κόμβου.
\item Τη δημόσια πληροφορία $M_i$.
\item Την τιμή $H_{i2}$.
\item Την ψηφιακή υπογραφή.
\item Μεταδεδομένα χρονικής σήμανσης.
\end{itemize}

Μετά τη δημιουργία του block πραγματοποιείται καταχώρηση στο
blockchain μέσω του chaincode. Το block αποκτά μοναδικό hash και
συνδέεται με το προηγούμενο block της αλυσίδας.

Η διαδικασία αυτή επαναλαμβάνεται από κάθε συμμετέχοντα καθώς το
πρωτόκολλο εξελίσσεται.

\subsection{Φάση Υπολογισμού Group Key}

Η φάση αυτή αποτελεί τον πυρήνα του πρωτοκόλλου.

Κάθε κόμβος λαμβάνει το τελευταίο block από το blockchain και
πραγματοποιεί επαλήθευση των κρυπτογραφικών υπογραφών μέσω
διγραμμικών pairings.

Εφόσον η επαλήθευση ολοκληρωθεί επιτυχώς, ο κόμβος παράγει τη δική
του συνεισφορά στο πρωτόκολλο μέσω της δημιουργίας νέου στοιχείου
$M_i$ και της αντίστοιχης υπογραφής.

Η νέα πληροφορία ενσωματώνεται σε νέο block το οποίο
καταχωρείται στο blockchain και προωθείται στον επόμενο
συμμετέχοντα.

Η διαδικασία συνεχίζεται μέχρι να φτάσει στον τελευταίο κόμβο της
ομάδας.
\subsection{Υπολογισμός του Τελικού Κλειδιού}

Ο τελευταίος κόμβος της ακολουθίας διαθέτει πλέον όλες τις
απαραίτητες συνεισφορές των συμμετεχόντων.

Χρησιμοποιώντας τις τιμές αυτές υπολογίζει το κοινό ομαδικό
κλειδί μέσω πράξεων πάνω στις ομάδες του pairing.

Το παραγόμενο αποτέλεσμα ανήκει στην ομάδα στόχο $G_T$ και
αποτελεί το κοινό μυστικό όλων των συμμετεχόντων.

Για επιπλέον ασφάλεια εφαρμόζεται συνάρτηση κατακερματισμού
SHA-512 πάνω στο παραγόμενο στοιχείο πριν χρησιμοποιηθεί από τις
ανώτερες εφαρμογές.
\subsection{Φάση Τελικής Επαλήθευσης}

Μετά τον υπολογισμό του τελικού κλειδιού ο τελευταίος κόμβος
διανέμει τις απαραίτητες παραμέτρους στους υπόλοιπους
συμμετέχοντες.

Κάθε κόμβος επανακατασκευάζει το κοινό κλειδί χρησιμοποιώντας τις
τοπικές του πληροφορίες και τις τιμές που έλαβε από τον τελευταίο
συμμετέχοντα.

Η ορθότητα του αποτελέσματος επαληθεύεται μέσω σύγκρισης των
κατακερματισμένων τιμών του group key.

Εφόσον όλοι οι κόμβοι παράγουν την ίδια τιμή κατακερματισμού,
θεωρείται ότι το πρωτόκολλο ολοκληρώθηκε επιτυχώς και όλοι οι
συμμετέχοντες διαθέτουν το ίδιο κοινό μυστικό.

\subsection{Υλοποίηση Chaincode}

Το chaincode αποτελεί το αποκεντρωμένο τμήμα της εφαρμογής και
εκτελείται στους peer κόμβους του Hyperledger Fabric. Η κύρια
αρμοδιότητά του είναι η αποθήκευση και διαχείριση των blocks που
παράγονται κατά την εκτέλεση του πρωτοκόλλου.

Η υλοποίηση πραγματοποιήθηκε στη γλώσσα Go αξιοποιώντας το
Fabric Contract API. Κάθε block αποθηκεύεται στο world state
του Fabric σε μορφή JSON και συνοδεύεται από πληροφορίες όπως
το αναγνωριστικό του block, το hash του προηγούμενου block,
κρυπτογραφικές παραμέτρους και χρονικές σημάνσεις.

Η λειτουργία AppendBlock αποτελεί τη σημαντικότερη συναλλαγή
του smart contract. Κατά την εκτέλεσή της δημιουργείται ένα
νέο block, υπολογίζεται το κρυπτογραφικό του αποτύπωμα και
αποθηκεύεται στο ledger.

Η ύπαρξη του πεδίου PrevHash δημιουργεί μία αλυσίδα
εξαρτήσεων μεταξύ των blocks, εξασφαλίζοντας ότι οποιαδήποτε
τροποποίηση ενός block θα επηρεάσει όλα τα επόμενα blocks της
αλυσίδας.
\section{Repository Layer}

Η πρόσβαση στο blockchain πραγματοποιείται μέσω ενός
Repository Layer το οποίο λειτουργεί ως ενδιάμεσο επίπεδο
μεταξύ της εφαρμογής και του Hyperledger Fabric.

Το υποσύστημα αυτό αξιοποιεί το Fabric Gateway API και
αναλαμβάνει τη δημιουργία ασφαλούς σύνδεσης με το δίκτυο.
Κατά την αρχικοποίηση φορτώνονται τα απαραίτητα πιστοποιητικά,
τα ιδιωτικά κλειδιά και οι πληροφορίες του οργανισμού.

Μέσω του Repository Layer αποκτάται πρόσβαση στο channel
του δικτύου καθώς και στο αντίστοιχο chaincode.

Η προσέγγιση αυτή επιτρέπει τον διαχωρισμό της λογικής
πρόσβασης στο blockchain από την επιχειρησιακή λογική
της εφαρμογής, βελτιώνοντας τη συντηρησιμότητα του
κώδικα.
\section{Service Layer}

Το Service Layer λειτουργεί ως αφαιρετικό επίπεδο πάνω από
το blockchain και προσφέρει υπηρεσίες υψηλού επιπέδου προς
το REST API.

Οι μέθοδοι του επιπέδου αυτού αντιστοιχούν στις βασικές
λειτουργίες που παρέχει το chaincode, όπως η εισαγωγή
νέων blocks, η ανάκτηση ολόκληρης της αλυσίδας και η
αναζήτηση συγκεκριμένων blocks.

Η χρήση του Service Layer επιτρέπει την απόκρυψη των
λεπτομερειών επικοινωνίας με το blockchain και την
παροχή ενός απλού προγραμματιστικού περιβάλλοντος
προς τα υπόλοιπα τμήματα της εφαρμογής.

\section{Αρχικοποίηση Pairings}

Η κρυπτογραφική λειτουργικότητα της εφαρμογής βασίζεται
στη βιβλιοθήκη JPBC η οποία παρέχει υποστήριξη για
διγραμμικές απεικονίσεις και πράξεις σε ελλειπτικές
καμπύλες.

Κατά την εκκίνηση κάθε κόμβου δημιουργούνται ή φορτώνονται
οι παράμετροι του pairing. Οι παράμετροι αυτές περιγράφουν
τις ομάδες \(G_1\), \(G_T\) και το πεπερασμένο σώμα στο
οποίο πραγματοποιούνται οι κρυπτογραφικές πράξεις.

Όλοι οι συμμετέχοντες χρησιμοποιούν κοινό γεννήτορα της
ομάδας \(G_1\), γεγονός που επιτρέπει την εκτέλεση
συμβατών πράξεων κατά τη διάρκεια του πρωτοκόλλου.

\subsection{Υλοποίηση BLS Υπογραφών}

Για την αυθεντικοποίηση των συμμετεχόντων χρησιμοποιούνται
ψηφιακές υπογραφές τύπου BLS.

Κάθε κόμβος διαθέτει ιδιωτικό κλειδί \(sk\) και δημόσιο
κλειδί \(pk\). Κατά τη δημιουργία ενός block παράγεται
υπογραφή πάνω στα δεδομένα του block η οποία αποθηκεύεται
μαζί με τις υπόλοιπες κρυπτογραφικές παραμέτρους.

Η επαλήθευση πραγματοποιείται μέσω bilinear pairings,
συγκρίνοντας δύο τιμές της ομάδας στόχου \(G_T\).

Με τον τρόπο αυτό κάθε κόμβος μπορεί να επαληθεύσει
την ταυτότητα του προηγούμενου συμμετέχοντα πριν
συνεχίσει την εκτέλεση του πρωτοκόλλου.


\chapter{Πειράματα και Μετρήσεις}

Στο παρόν κεφάλαιο παρουσιάζεται η πειραματική αξιολόγηση της προτεινόμενης υλοποίησης του πρωτοκόλλου Blockchain Dynamic Group Key Agreement (BDGKA).
Στόχος των πειραμάτων είναι η διερεύνηση της αποδοτικότητας, της επεκτασιμότητας και της πρακτικής εφαρμοσιμότητας του πρωτοκόλλου σε ένα πραγματικό περιβάλλον blockchain βασισμένο στο Hyperledger Fabric.

Η αξιολόγηση πραγματοποιήθηκε σε περιβάλλον Linux, με χρήση Docker containers για την ανάπτυξη του δικτύου Hyperledger Fabric.
Το blockchain δίκτυο αποτελείται από δύο οργανισμούς (Organizations), έναν Orderer, δύο Peers και μία Certificate Authority για κάθε οργανισμό.
Οι κόμβοι του πρωτοκόλλου υλοποιήθηκαν σε Java χρησιμοποιώντας το πλαίσιο ανάπτυξης Spring Boot, ενώ οι κρυπτογραφικές λειτουργίες βασίστηκαν στη βιβλιοθήκη JPBC για την υποστήριξη bilinear pairings και ελλειπτικών καμπυλών.

Για την αξιολόγηση του πρωτοκόλλου εξετάστηκαν τρεις βασικές κατηγορίες μετρικών:
(i) ο συνολικός χρόνος δημιουργίας του ομαδικού κλειδιού,
(ii) το επικοινωνιακό κόστος σε αριθμό ανταλλασσόμενων μηνυμάτων και

Ο συνολικός χρόνος δημιουργίας του ομαδικού κλειδιού αντιστοιχεί στο χρονικό διάστημα από την έναρξη του πρωτοκόλλου έως την επιτυχή παραγωγή και επαλήθευση του κοινού μυστικού κλειδιού από όλους τους συμμετέχοντες.

func (block *Block) hash() error {
	tempBlock := *block
	tempBlock.CurrentHash = ""
	tempBlockBytes, err := json.Marshal(tempBlock)
	if err != nil {
		return fmt.Errorf("failed to marshal block: %v", err)
	}
	hash_bytes := sha256.Sum256(tempBlockBytes)
	block.CurrentHash = hex.EncodeToString(hash_bytes[:])
	return nil
}

	if err != nil {
		return fmt.Errorf("previous block error: %vs", err)
	}
	var prevBlock *Block
	var prevHash string
	if prevBlockIdBytes != nil {
		prevBlockId := string(prevBlockIdBytes)
		prevBlock, err = contract.ReadBlock(ctx, prevBlockId)
		if err != nil {
			return fmt.Errorf("previous block error: %v", err)

func (c *BDGKAContract) GetAllBlocks(ctx contractapi.TransactionContextInterface) ([]*Block, error) {
	resultsIterator, err := ctx.GetStub().GetStateByRange("", "")
	if err != nil {
		return nil, fmt.Errorf("failed to get state by range: %v", err)
	}
	defer resultsIterator.Close()
	var blocks []*Block
	for resultsIterator.HasNext() {
		queryResponse, err := resultsIterator.Next()
		if err != nil {
			return nil, fmt.Errorf("failed to iterate results: %v", err)
		}
		key := queryResponse.Key
		if key == "LAST_BLOCK" {
			continue
		}
		var block Block
		err = json.Unmarshal(queryResponse.Value, &block)
		if err != nil {
			return nil, fmt.Errorf("failed to unmarshal block: %v", err)
		}
		blocks = append(blocks, &block)
	}
	return blocks, nil
}
